This plan delivers DOC-04 in the UI: the application detail tells the user which CV and which cover letter went to that company and lets them download each one. It also adds `formatFileSize`, which the library screen (05-08) reuses, and the sentence the Phase 2 delete dialog promised.

## Assumptions and decisions (explicit, for the user to review)

- **Keyed documents effect (RESEARCH Pattern 10).** Key = `${applicationId}#${attempt}:${cv ?? ""}:${coverLetter ?? ""}`; it runs only when the application result is ok; mutations that return the same links keep the key, so nothing is refetched; an aborted or stale response never writes.
- **Live regions.** The section adds exactly one `role="status"` region (sr-only «Cargando documentos…» while any linked row loads); a failed row's sentence sits in that row inside an always-mounted `aria-live="polite"` slot without a role, so the detail's status-region count goes from 3 to 4. Both rows are always present (UI-SPEC §3).
- **`download` attribute kept** (RESEARCH Assumption A2, UI-SPEC §3); its browser behaviour on an error is a backstop checked in the UAT.
- **formatFileSize unit rule.** B for anything under 1024 bytes (so 1023 stays «1023 B»); from 1024 bytes on, the largest of KB and MB whose value rounded to one decimal is at least 1: MB as soon as the KB value rounded to one decimal is 1024 or more, otherwise KB. So 5242880 reads «5 MB» (5120 KB is over 1024), 1258291 reads «1,2 MB» (1228,8 KB is over 1024), 1048575 reads «1 MB» rather than «1024 KB», and 1536 reads «1,5 KB»; no unit above MB (5 MB ceiling).
- **The Phase 2 test «never renders linked documents» is replaced** by the documents-section tests (Phase 2 SC4 said the section waits for Phase 5).
