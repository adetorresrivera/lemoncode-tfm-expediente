## Assumptions and decisions (explicit, for the user to review)

- **Delete order (Claude's discretion in D-11).** 404 check → 409 check → `repository.deleteById` → `storage.delete(key)` best effort with its error swallowed. The forbidden state is a record pointing to a missing object; the reverse (an orphan object) is invisible and harmless, and `DeleteObject` is idempotent (RESEARCH Pattern 5). Nothing is logged, so no key or file name can leak.
- **Messages.** 404 «Documento no encontrado» (record or malformed id, D-09), 404 «Archivo no encontrado» (object missing, D-10), 409 with the sentence of D-29 so API and UI say the same thing.
- **Link/delete race not guarded (spec-less edge DOC-05 «unclassified», flagged assumption).** A link saved between the 409 check and the delete could point to a deleted document. Single-user local app; accepted as T-05-14. 05-03 makes the applications service reject links to unknown documents, so a later save of that application surfaces the problem as a 400.
- **Indexes.** `documents`: `{ createdAt: -1 }` named `createdAt_-1` (list order). `applications`: `{ cvDocumentId: 1 }` and `{ coverLetterDocumentId: 1 }` (in-use check). Added in `ensureIndexes`, which the tests already run.
- **usedBy is computed per request** with one aggregation over `applications` (RESEARCH Pattern 5), never stored.
- **List filter validation.** `documentQuerySchema` on `queryInput(c.req.queries())`: a repeated `type` becomes an array and fails the enum (400), like the other query schemas.
- **Spec-less edge probes lifted here:** DOC-04 concurrency (object gone after the metadata was read), DOC-06 adjacency, empty and ordering.

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-10 | Tampering | Content-Disposition header (CR/LF or non-Latin-1 in fileName) | high | mitigate | Header value only from `contentDisposition` (printable-ASCII fallback plus RFC 5987 `filename*`); fileName already stripped of control characters in 05-01; test with accents |
| T-05-11 | Spoofing | browser rendering a downloaded file inline (stored XSS) | high | mitigate | `Content-Disposition: attachment`, `Content-Type` = detected mime only, global `secureHeaders` nosniff asserted in the download test |
| T-05-12 | Information disclosure | id oracle on :id routes | low | mitigate | `parseObjectId(raw, "Documento no encontrado")`: malformed and unknown ids answer the same 404 |
| T-05-13 | Tampering | deleting a linked document (rule 4) | medium | mitigate | `isInUse` check before `deleteById`, 409 DOCUMENT_IN_USE; tests for CV and cover-letter links |
| T-05-14 | Tampering | link saved between the 409 check and the delete | low | accept | Single-user local app; 05-03 rejects links to unknown documents, so the stale link surfaces as a 400 on the next save |
| T-05-15 | Denial of service | download buffering the object in memory | low | mitigate | `transformToWebStream()` piped to `c.body(stream)`; no `transformToByteArray` |
| T-05-16 | Tampering | query injection through ?type= | medium | mitigate | `documentQuerySchema` enum through `queryInput`; arrays and unknown values answer 400; the filter is built from the parsed enum only |
| T-05-SC | Tampering | npm installs | high | mitigate | No package installed |
