## Phase Goal

**As a** job seeker, **I want to** paste an offer and get a reviewable draft of the application form, **so that** I fill an application in seconds without losing anything I already typed.

This plan closes AI-09: the analyzed offer is kept with the application, survives edits, and comes back into the panel when the user edits the application later.

<objective>
Persist `offerText` on PUT (the Phase 2 hand-over), carry it through the form VM and mappers, set it only from a successful analysis (third argument of `mergeExtractionIntoForm`, RESEARCH Q5), and prefill the edit-mode textarea with the stored text.

Purpose: the original offer is the record behind every draft; the demo shows it in the detail after saving.
Output: API whitelist change with rewritten tests; VM/mapper changes with every merge call site updated; hook and container wiring with flow tests.
</objective>

## Assumptions (explicit, for the user to review)

- RESEARCH Q5 (user decision 2026-10-31): `mergeExtractionIntoForm` takes a required third argument, the analyzed text; D-04's two-argument signature cannot set `offerText` otherwise. The other D-04 outputs are unchanged. Required rather than optional so `tsc` (run by the pre-commit hook and by Task 2's verify) finds any call that was not updated.
- The text sent to the API and stored is `draft.trim()`; the API trims it for validation anyway, so the stored text equals what was analysed.
- PUT semantics change on purpose: an omitted or null `offerText` now clears the stored text (the schema default is null). The edit form always sends the loaded value, which is why the VM carries it from the first render. The Phase 5 hand-over for the document ids is unchanged.
