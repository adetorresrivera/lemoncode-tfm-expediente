## Phase Goal

**As a** job seeker, **I want to** paste an offer and get a reviewable draft of the application form, **so that** I fill an application in seconds without losing anything I already typed.

This plan closes the phase: the deliverable image proves the new route, the full suite is green, the real local model is measured on the three fixtures, and the user decides, with evidence in hand, whether the literal prompt and `gemma4:e2b` are good enough for the defence.

<objective>
Add the offers route to the compose smoke and run the phase gate; run the D-24 manual test against Ollama and record the table; then stop at a blocking human checkpoint for the UI pass and the D-25 decision (user decision 2026-10-31: «the manual run should be a human-verify checkpoint at the end of the phase»).

Purpose: the demo depends on a model the tests never call; this is the only place its real quality and speed are measured before the defence.
Output: smoke assertion, green gate, D-24 table in the SUMMARY, the user's D-25 decision.
</objective>

## Assumptions (explicit, for the user to review)

- The smoke checks the route with a too-short text only: a real extraction in the compose image would call Ollama and can take tens of seconds; the full model path is measured by `try-extract` in the devcontainer instead.
- `try-extract` runs in-process (no server, no database) with the devcontainer variables `LLM_PROVIDER=ollama`, `LLM_BASE_URL=http://ollama:11434`, `LLM_MODEL=gemma4:e2b`. Nothing heavy runs at the same time (RESEARCH Pitfall 12: memory is tight); the first call includes the model load (about +10 s).
- D-25 trigger: any fixture over 60 s, or a correctness problem the user judges unacceptable (Pitfall 7 pattern: tag labels equal to «stack», «nice_to_have» or «language», company null when it is in the text).
- Any change the user approves at the checkpoint (adding the two prompt lines from Pitfall 7, another local model, or the cloud fallback) is applied as a follow-up (`/gsd-quick`) after this plan: a prompt change edits `EXTRACTION_SYSTEM_PROMPT` and the docs/AI-EXTRACTION.md block together so the verbatim test keeps passing, then reruns `try-extract`; a model change edits `LLM_MODEL` in `.env.example`, `compose.yml` and docs/ARCHITECTURE.md.
