## Phase Goal

**As a** job seeker, **I want to** log the interview rounds of an application, **so that** its process history and status stay in sync without extra bookkeeping.

This plan lets the user correct and remove rounds from the detail (INT-03): Task 1 adds both endpoints with real-Mongo tests, then Task 2 delivers the edit flow and Task 3 the delete flow in the detail.

<objective>
Task 1: `PUT /:id/interviews/:interviewId` (per-key `$set` with `arrayFilters`) and `DELETE /:id/interviews/:interviewId` (`$pull`, 200 with the application), with their real-Mongo tests. Task 2: the edit mode of the existing dialog, opened from a Pencil button on each row, with «Ronda» required in that mode (D-28). Task 3: a confirmation `AlertDialog` opened from a Trash2 button, with focus moved to «Añadir ronda» after the delete.

Purpose: a mistyped or cancelled round can be fixed in seconds, and the status never moves as a side effect.
Output: two endpoints with real-Mongo tests; edit mode, row actions and the delete dialog in the detail pod with tests.
</objective>

## Assumptions and decisions (explicit, for the user to review)

- **Edit-mode «Ronda» is required (D-28, user decision 2026-11-02; resolves RESEARCH open question 1).** In the edit dialog «Ronda» is an integer of 1 or more and cannot be left empty: its label carries the ` *` marker and the input `aria-required`, its hint «Si lo vacías, se asigna la siguiente.» is not rendered (D-09 applies to «Añadir ronda» only), and an empty field shows the existing invalid-round copy «La ronda debe ser un número entero de 1 o más.» (UI-SPEC copy table, no new string). PUT stays a per-key `$set` with `arrayFilters` (D-05): the client computes no number on edit and PUT uses no pipeline, so round numbering stays in the API tier (RESEARCH Responsibility Map). A PUT body without `round` (other clients) keeps the stored round: the key is left out of the `$set` (D-03 «editable en PUT»).
- **APP-13 is claimed only for its rounds part** (CONTEXT.md phase boundary: «la parte de rondas de APP-13 (`updatedAt`)»): PUT and DELETE set `updatedAt`, as POST does since 04-01.
- **API task first (scope split).** Edit and delete share every API file, so one API task adds both and proves them over HTTP; the two web tasks then each deliver one user-visible flow on top of it.
- **`:interviewId` is a plain string** compared by equality (filter, `arrayFilters`, `$pull`); it is not passed to `parseObjectId`, whose message names the application (RESEARCH Pattern 3). A malformed or unknown round id on an existing application answers «Ronda no encontrada».
- **Focus after a delete.** The deleted row's buttons are gone, so after success focus moves to the section's «Añadir ronda» (UI-SPEC «Focus after a successful delete», the one programmatic focus move of the phase); after a cancel it returns to the delete button that opened the dialog, through the same `onCloseAutoFocus` mechanism as the round dialog, falling back to «Añadir ronda» when the opener is no longer connected.
- **«Eliminando…» state** comes from `actions.busy` (nothing else can run while the modal is open); the failure flag is local to the section.
- Spec-less edge probes lifted here: INT-03 boundary, precision, idempotency and concurrency (API rows in Task 1, the web boundary rows in Task 2).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → PUT/DELETE /api/applications/:id/interviews/:interviewId | Untrusted ids and body change or remove stored rounds |
| API → MongoDB update operators | A path parameter is used in the filter, `arrayFilters` and `$pull` |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-10 | Tampering | `:interviewId` path parameter | medium | mitigate | Always a string compared by equality in the filter, `arrayFilters` and `$pull`; never turned into an operator or a key; the body is never spread into the update |
| T-04-11 | Tampering | PUT body → element id (mass assignment) | medium | mitigate | Per-key `$set` of type, scheduledAt, mode, notes, outcome and round only; the id key is never written; test that a body id is ignored |
| T-04-12 | Tampering | resurrecting a deleted round | medium | mitigate | Filter requires the element (`"interviews.id"`), no insert-on-miss option; DELETE → PUT 404 test and concurrent PUT/DELETE test |
| T-04-13 | Tampering | accidental deletion | low | mitigate | AlertDialog confirmation with initial focus on «Conservar ronda»; one DELETE in flight (busy guard) |
| T-04-14 | Information disclosure | distinct 404 messages for application and round | low | accept | Single-user local app without accounts (`ownerId` null); the two messages only tell the UI which resource is missing |
| T-04-SC | Tampering | npm installs | high | mitigate | No package installed; lockfile unchanged |
