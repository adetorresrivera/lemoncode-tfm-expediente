### Dialog primitive adaptation

Add with `npx shadcn add dialog` (official registry), then adapt the generated file to the project chrome already used by `alert-dialog.tsx`; do not leave the registry defaults:

- Overlay: `fixed inset-0 z-50 bg-sidebar/70`, fade in/out, `motion-reduce:animate-none motion-reduce:transition-none`.
- Content: `fixed top-1/2 left-1/2 z-50 grid max-h-[calc(100dvh-2rem)] w-[calc(100%-2rem)] max-w-lg -translate-x-1/2 -translate-y-1/2 gap-4 overflow-y-auto rounded-md border border-border bg-popover p-4 text-popover-foreground shadow-lg sm:p-6`, same fade, same `motion-reduce` rules. (Padding is `p-4` below 640 px so the 360 px form keeps 296 px of inner width; `alert-dialog.tsx` keeps its `p-6`.)
- Title: `font-serif text-base font-semibold leading-[1.2] text-foreground`. Description: `text-base text-muted-foreground`.
- Footer: `flex flex-col-reverse gap-2 sm:flex-row sm:justify-end` (primary on top on mobile).
- Close button (X): `absolute top-2 right-2 size-11` ghost, `X` icon `size-4 strokeWidth={1.5}`, `aria-label="Cerrar"`, focus ring `focus-visible:ring-2 focus-visible:ring-ring`. It is the **last** child in the DOM (after the form) so the first tabbable element, and Radix's initial focus, is the form's first field; visually it is top-right. The title gets `pr-10` so it never runs under the X.
- Overlay click does **not** close the dialog (`onInteractOutside={(e) => e.preventDefault()}` on the content): a stray click must not discard up to 5.000 characters of notes. Esc, the X and «Descartar cambios» close it.

## Spacing Scale

Declared values (multiples of 4). Same section-card rhythm as every other detail section (`rounded-md border border-border bg-card p-4 lg:p-6`, `gap-4` between children).

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | `py-1` vertical padding of the outcome badge; `gap-1` label ↔ control ↔ hint/error inside a field; gap between the two icon buttons of a round |
| sm | 8px | `gap-2` between meta items when they wrap; icon ↔ text in badge and buttons; footer button gap; `pt-2` above the feedback line |
| md | 16px | Section/list `gap-4`; item vertical rhythm (`pt-4` below the divider); dialog `gap-4` between fields; `gap-x-4` between date, mode and badge; dialog padding `p-4` below 640 px |
| lg | 24px | Section padding from `lg` (1024 px) `lg:p-6`; dialog padding from `sm` (640 px) `sm:p-6`; `gap-6` between sections (inherited) |
| xl | 32px | not used |
| 2xl | 48px | not used |
| 3xl | 64px | not used |

Exceptions:
- Touch targets are 44 px: «Añadir ronda», dialog buttons, notes trigger and toggle items are `h-11` (toggle items `min-h-11`); the edit/delete icon buttons are `size-11` (44 × 44), which is a multiple of 4. The dialog X is `size-11`.
- Icon sizes: lucide `size-4` (16 px) in buttons and badge, as everywhere.
- Dialog width `max-w-lg` (512 px) on desktop; `w-[calc(100%-2rem)]` below that, so 328 px at 360 px viewport (inherited from `alert-dialog.tsx`).
- Textarea: `min-h-32` (128 px, the component default), `resize-y`.

## Section Layout and Interaction Contract

### Focal point

The detail page keeps «Editar» as its single primary action. Inside the section the focal point is the **«Añadir ronda»** outline button at the top right of the card (and, once a round exists, the newest information is the list under it). In the demo flow the eye must then land on the **header badge and the status history changing together** after the first save; that is the reason the feedback line says «Estado cambiado a En entrevistas.» and why the VM is replaced as a whole (D-13). No extra emphasis, highlight or animation is added to the badge.

### Placement and anatomy

`InterviewsSection` sits in the main column between `<TagsSection>` and `<NotesSection>` (`application-detail.component.tsx`, D-21). Same card chrome as the sibling sections, `aria-labelledby="interviews-heading"`.

```
┌ section (card, flex flex-col gap-4) ──────────────────────────┐
│ ┌ header (flex flex-wrap items-center justify-between gap-2) ┐│
│ │ h2  Rondas de entrevista            [+ Añadir ronda]       ││  Button outline h-11, Plus icon
│ └────────────────────────────────────────────────────────────┘│
│ <div role="status" aria-live="polite">  feedback  </div>       │  always mounted, zero height when empty
│ ── list ───────────────────────────────────────────────────────│
│ h3 Ronda 1 · Técnica                          [✎] [🗑]         │  actions: size-11 ghost icon buttons
│ 5 nov. 2026, 10:30    Online    ( Clock  Pendiente )          │  meta row, wraps
│ [ Ver notas        v ]                                         │  only when notes exist
│ ─────────────────────────────────────────────────────────────  │  divider between rounds
│ h3 Ronda 2 · Cultural …                                        │
└────────────────────────────────────────────────────────────────┘
```

- **List**: `<ol className="flex flex-col gap-4">`; each `<li className="flex min-w-0 flex-col gap-2 border-t border-border pt-4 first:border-t-0 first:pt-0">`. Rounds are separated by a hairline, not nested cards (DESIGN.md: border over shadow). The VM arrives already ordered (D-07); the component does not sort.
- **Item header**: `flex items-start justify-between gap-2`. Title `h3` `min-w-0 break-words font-serif text-base font-semibold leading-[1.2]` (a long type never overflows; it wraps). Actions `flex shrink-0 gap-1`.
- **Icon buttons** (D-20): `<Button type="button" variant="ghost" className="size-11" aria-label="Editar ronda N">` with `<Pencil aria-hidden="true" strokeWidth={1.5} />`; same for `Trash2` with `aria-label="Eliminar ronda N"`. Always visible (no hover reveal), at every width. Icon `size-4` is the Button default.
- **Meta row**: `flex flex-wrap items-center gap-x-4 gap-y-2`. Items in order:
  1. Date: `<time dateTime={iso} className="text-base">` with the formatted «5 nov. 2026, 10:30»; when null, `<span className="text-base text-muted-foreground">Sin fecha</span>` (no `<time>`).
  2. Mode: `<span className="text-base text-muted-foreground">` with the label.
  3. Outcome: `InterviewOutcomeBadge`.
  Each item is preceded by its `sr-only` prefix («Fecha: », «Modalidad: », «Resultado: ») so a screen-reader pass reads «Fecha: 5 nov. 2026, 10:30 Modalidad: Online Resultado: Pendiente».
- **Outcome badge** (`InterviewOutcomeBadge`): `inline-flex items-center gap-2 rounded-sm bg-muted px-2 py-1 text-sm font-semibold text-foreground`, icon first (`Clock` pendiente, `Check` superada, `X` no superada), each `aria-hidden="true" strokeWidth={1.5} className="size-4"`, then the label. Same shape as `StatusBadge` (`rounded-sm px-2 text-sm font-semibold`) minus the coloured dot, with vertical padding `py-1` (4 px, on the 4-point scale) instead of the status badge's `py-0.5`, so it reads as a sibling but is clearly not a status.
- **Notes** (only when `notes` is non-null): `Collapsible`, closed by default, trigger identical to `offer-text-section.tsx` (`Button variant="ghost" className="h-11 w-full justify-between px-4"`, `ChevronDown` rotating 180° when open, `motion-reduce:transition-none`). Content `pt-4`: `<p className="whitespace-pre-wrap break-words text-base">`, plain text node, never HTML. Notes stay unmounted until opened (Radix default).
- **Empty state**: when there are no rounds, render only `<p className="text-muted-foreground">Aún no hay rondas. Añade la primera cuando te convoquen.</p>` below the header; the «Añadir ronda» button stays in the header. No illustration, no second button.
- **Feedback line**: container `<div role="status" aria-live="polite">` is always mounted, directly under the header, with no padding and no gap of its own (so it takes zero height when empty). When a message exists it renders `<div className="pt-2"><RequestStatus kind="success" message={…} /></div>`. Disappears after `SUCCESS_VISIBLE_MS` (5 s). This is the only announcement of a round mutation; the status-change feedback slot in the header is **not** used for the automatic state change (no double announcement).
- **Busy state** (D-16): while any mutation (status or round) is in flight, «Añadir ronda», every edit and delete icon button and the status selector are `aria-disabled="true"` (never `disabled`, so focus is not dropped) with `aria-disabled:pointer-events-none aria-disabled:opacity-50`, and their click handlers return early. Buttons inside the open dialogs follow the dialog rules below.

### Add / edit dialog

One `InterviewDialog` instance per section, controlled: state is `closed | { mode: "add" } | { mode: "edit", interviewId }`. It is opened from «Añadir ronda» or an edit icon button; Radix returns focus to the element that was focused before it opened (D-20).

```
┌ DialogContent ─────────────────────────────── [X] ┐
│ Añadir ronda                         (h2, serif)   │
│ Anota los datos de la entrevista. Solo el tipo...  │
│ <form noValidate class="flex flex-col gap-4">      │
│   Tipo *                    [Elige un tipo     v]  │
│   Ronda                     [ 3               ]    │
│     Si lo vacías, se asigna la siguiente.          │
│   Fecha y hora              [ dd/mm/aaaa --:-- ]   │
│     Opcional. Hora en tu zona horaria.             │
│   Modalidad                 [Online|Presencial|Teléfono]
│   Resultado                 [Pendiente|Superada|No superada]
│   Notas                     [ textarea         ]   │
│                                        0 / 5.000   │
│   <div role="status" aria-live="polite"> error </div>
│   [Guardar ronda]  [Descartar cambios] (mobile stack)│
│ </form>                                            │
└────────────────────────────────────────────────────┘
```

Field order and controls (D-18, D-19):

| Field | Control | Default (add) | Notes |
|-------|---------|---------------|-------|
| Tipo | `NativeSelect` + `Label htmlFor`, `aria-required="true"` | `""` («Elige un tipo») | Required; error under the field. |
| Ronda | `Input type="number" inputMode="numeric" min={1} step={1}` | max + 1 (D-09) | Hint always visible. |
| Fecha y hora | `Input type="datetime-local"` | empty | Empty → `null` («Sin fecha»). Past dates allowed (D-12), no error. |
| Modalidad | `ToggleGroup type="single" variant="outline"` | `online` | Group named by a visible label via `aria-labelledby`. |
| Resultado | `ToggleGroup type="single" variant="outline"` | `pendiente` | Same. |
| Notas | `Textarea`, `maxLength={5000}`, `resize-y` | empty | Counter below, right-aligned, `font-mono tabular text-sm text-muted-foreground`, **not** a live region. |

- On a `sm` (640 px) viewport and up, «Tipo» and «Ronda» share a row (`grid gap-4 sm:grid-cols-2`); below that every field is full width and stacked.
- **Toggle groups**: single selection is mandatory: Radix reports `""` when the active item is pressed again, and the handler **ignores empty values** so a value is always selected (same guard as `theme-toggle.tsx`). The group is `className="grid w-full grid-cols-3"`; each item `className="h-auto min-h-11 w-full justify-center whitespace-normal px-2 text-center leading-tight"` plus the selected treatment `data-[state=on]:bg-primary data-[state=on]:text-primary-foreground data-[state=on]:hover:bg-primary/90 data-[state=on]:hover:text-primary-foreground`. **No icons** in these items: at 296 px of inner width, three equal columns are 98 px and «No superada» in 14px/600 semibold needs ≈ 80 px plus 16 px padding, so the label may wrap onto two lines instead of overflowing, which is why `whitespace-normal` and `h-auto min-h-11` are mandated. The groups never stack vertically. Arrow keys move between items (Radix roving focus); Space/Enter selects.
- **Validation**: schema from `@tfm/contracts`. Errors appear under the field using the `FormField` error line (`CircleAlert` + text). Validate on submit, then re-validate on change. On a failed submit, focus moves to the first invalid field (in practice «Tipo»). The empty «Ronda» is **valid** (omitted from the input, D-09).
- **Buttons**: «Guardar ronda» is `type="submit"` `variant="default"` `h-11`, «Descartar cambios» is `type="button"` `variant="outline"` `h-11`; both `w-full sm:w-auto`. Enter inside a text/number/datetime input submits; Enter inside the textarea inserts a newline.
- **Pending save (D-13)**: «Guardar ronda» becomes «Guardando…» and `aria-disabled="true"` (submit handler returns early); «Descartar cambios», the X, Esc and overlay are ignored (the dialog cannot close while the request is in flight, same rule as `delete-dialog.tsx`). The fields are **not** disabled (a disabled field would drop keyboard focus); edits typed during the request are simply not sent, because the values captured at submit are the ones in flight. No spinner icon; the label change is the cue.
- **Success**: dialog closes, VM replaced, feedback line announces (D-15). Focus returns to the control that opened the dialog (add: «Añadir ronda»; edit: that round's edit button, which keeps its identity because items are keyed by `id`).
- **Failure**: dialog stays open, every typed value is preserved, `RequestStatus kind="error"` appears in the in-dialog live region right above the footer: `<div role="status" aria-live="polite">`, always mounted. The error is cleared when the user starts a new submit or reopens the dialog.
- **Edit mode**: opens with the round's values; a stored `scheduledAt` is converted to local `datetime-local` format; a null one shows an empty control. Title «Editar ronda {N}».
- **Reopening**: every opening resets the form to its defaults (add) or the round's current values (edit); nothing from a cancelled attempt survives.

### Delete confirmation

One controlled `InterviewDeleteDialog` (`AlertDialog`) per section, same structure and behaviour as `delete-dialog.tsx`:

- Initial focus lands on «Conservar ronda» (Radix focuses Cancel). Overlay click closes it (existing `onOverlayClick` seam), except while deleting.
- While deleting: «Eliminar ronda» becomes «Eliminando…», both buttons `aria-disabled`, every close request ignored. On success the dialog closes (D-14).
- Error: `RequestStatus kind="error"` «No se pudo eliminar la ronda. Inténtalo de nuevo.» in an always-mounted `role="status" aria-live="polite"` container inside the dialog; the dialog stays open and the confirm button is available again.
- **Focus after a successful delete**: the deleted row's buttons no longer exist, so focus is moved programmatically to the section's **«Añadir ronda»** button (stable element in the same section). This is the one programmatic focus move of the phase.

### Keyboard order

Tab order in the section: «Añadir ronda» → for each round: edit icon → delete icon → «Ver notas» (if any) → next round. Dialogs trap focus (Radix): Tipo → Ronda → Fecha y hora → Modalidad (one tab stop, arrows inside) → Resultado (one tab stop) → Notas → «Guardar ronda» → «Descartar cambios» → X. Esc closes (unless saving). Visible focus everywhere is the project ring (`focus-visible:ring-2 focus-visible:ring-ring`).

### Responsive (from 360 px, no horizontal scroll)

- Section, list items and header children are `min-w-0`; the header wraps (`flex-wrap`) when «Rondas de entrevista» and «Añadir ronda» do not fit one line at 360 px (approximately 296 px of inner width).
- The meta row wraps; long labels break (`break-words`); the two 44 px icon buttons plus `gap-1` take 92 px and the title uses the rest.
- Dialog: 328 px wide at 360 px, `max-h-[calc(100dvh-2rem)]` with internal scroll, so the footer is reachable with the soft keyboard open by scrolling the dialog; buttons stack full-width with «Guardar ronda» on top.
- `datetime-local` and `number` inputs are `w-full min-w-0` (the `Input` default) so the native picker never widens the dialog.

### Motion

Only: dialog and overlay fade (`data-[state]` animate in/out, as `alert-dialog.tsx`), notes chevron rotation. All honour `motion-reduce`. No animation on list changes, on the badge or on the history.
