## Assumptions and decisions (explicit, for the user to review)

- **Injected clock (D-06 as amended on 2026-11-06 by the user at plan review).** Both services already take `now` as their last argument, so the runner advances a mutable clock before each call and every timestamp (history, `updatedAt`, `appliedAt`, document `createdAt`) is written by the real rules. The only direct Mongo write is the `seed: true` mark.
- **Histories are walked, never created late.** The application is created as `guardada` and moved with `changeStatus`; 06-02 extends the same walk to rounds.
- **PDF generator not committed.** The executor writes the RESEARCH «Minimal readable PDF» generator in a scratch file outside the repo, runs it once, and commits only the output (D-07: no PDF library). Text is Latin-1 only. English asset file names (CLAUDE.md).
- **The tracer run targets the devcontainer database.** `npm run seed` in the verify writes to `tfm` / `tfm-assets` (MONGO_URL and S3_BUCKET of the devcontainer). A normal run only replaces `seed: true` records, so the user's own records survive (D-02). `--reset` arrives in 06-02 and is never run against the devcontainer database by a verify.
- **Edge coverage (spec-less fallback).** DEMO-01 was not classified by the edge probe (flagged assumption: its edges are the explicit truths above: two runs, a pre-existing user record, links and downloads). DEMO-05 idempotency is resolved here as an explicit truth; interrupted runs are handled in 06-02.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| seed script → Mongo / Silo | A CLI with full write access to the configured database and bucket |
| committed assets → upload pipeline | Repository files enter the same file checks as user uploads |
| seeded data → API responses | Storage-only fields must stay out of the public JSON |
