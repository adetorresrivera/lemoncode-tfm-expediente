## Assumptions and decisions (explicit, for the user to review)

- **Injected clock instead of patching dates (D-06).** Both services already take `now` as their last argument, so the runner advances a mutable clock before each call and every timestamp (history, `updatedAt`, `appliedAt`, document `createdAt`) is written by the real rules. D-06 allows patching dates afterwards; with the clock nothing needs patching, so the only direct write is the `seed: true` mark. Same outcome, fewer hand-written timestamps.
- **Histories are walked, never created late.** Each application is created as `guardada` or `enviada` and moved with `changeStatus` / `addInterview`, so `en_entrevistas` always comes from the rule after `enviada`.
- **Status distribution (Claude's discretion, D-04).** enviada 3, en_entrevistas 3, guardada 2, oferta_recibida 1, aceptada 1, rechazada 1, descartada 1. 3-round applications: one `en_entrevistas` (its third round in the future), the `oferta_recibida` and the `rechazada`. One-round applications: the other two `en_entrevistas` and the `aceptada`.
- **PDF generator not committed.** The executor writes the RESEARCH «Minimal readable PDF» generator in a scratch file outside the repo, runs it once, and commits only the three outputs (D-07: no PDF library). Text is Latin-1 only (accents and `·` are fine; avoid the euro sign and long dashes).
- **The tracer run targets the devcontainer database.** `npm run seed` in the verify writes to `tfm` / `tfm-assets` (MONGO_URL and S3_BUCKET of the devcontainer). A normal run only replaces `seed: true` records, so the user's own records survive (D-02). `--reset` arrives in 06-02 and is never run against the devcontainer database by a verify.
- **Edge coverage (spec-less fallback).** DEMO-01 was not classified by the edge probe (flagged assumption: its edges are the explicit truths above, two runs, a pre-existing user record, links and downloads). DEMO-05 idempotency is resolved here as an explicit truth; DEMO-05 interrupted/parallel runs are handled in 06-02.
