## Phase Goal

**As a** presenter, **I want to** have seeded data, a README and a responsive, accessible UI, **so that** the full demo runs in under 2 minutes on a clean machine.

This plan removes three live-demo traps: a close button that silently does nothing, a delete dialog that reopens with an old error, and an empty-state flash while the filtered list reloads.

<objective>
Dialog close lock with spoken feedback (D-19, 05 WR-03, UI-SPEC A6), reset-on-open for the delete dialogs (D-16, 02 WR-03) and a list refetch without an empty flash (D-16, 02 WR-04), each finding flipped to `fixed`.

Purpose: DEMO-04 (keyboard and screen-reader feedback) and DEMO-05 (the filter step of the demo flow).
Output: `closeDisabled` on `DialogContent`, sentences in two dialogs, `resetDeleteError`, list rendering rule, tests, dispositions.
</objective>

## Assumptions and decisions (explicit, for the user to review)

- **Delete dialogs keep their silent Esc lock.** They are AlertDialogs without an X; their button already reads «Eliminando…». Adding the sentence there needs more than the shared prop, so per UI-SPEC §3 it is recorded as known debt, not built.
- **No state effects for the sentence.** The close-blocked flag is cleared during render when the lock ends (the same "remember the last value" pattern as `interview-delete-dialog.tsx`), because `eslint-plugin-react-hooks` 7 rejects `setState` inside effects.
- **Counter during refetch.** Keeps the previous value when previous cards stay; becomes `null` (no counter) while the skeleton shows.
