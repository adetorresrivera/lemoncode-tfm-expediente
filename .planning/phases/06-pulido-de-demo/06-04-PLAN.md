## Phase Goal

**As a** presenter, **I want to** have seeded data, a README and a responsive, accessible UI, **so that** the full demo runs in under 2 minutes on a clean machine.

This plan replaces the two English default screens with Spanish ones in the design-system voice and makes the shell keyboard-honest: a skip link, a visible focus ring on the navy sidebar and 44 px targets.

<objective>
Spanish not-found and route-error screens wired as router defaults and as the root error component (D-18, 01 WR-07), then the shell changes of UI-SPEC §2 (skip link, `sidebar-ring`, touch targets, wordmark size, stacked theme toggle) with their DESIGN.md write-back.

Purpose: DEMO-04 (keyboard, focus, labels) and DEMO-03 (shell at 360 px).
Output: `RouteNotFound`, `RouteError`, `RootError`, router wiring, shell changes, tests, docs.
</objective>

## Assumptions and decisions (explicit, for the user to review)

- **Where the screens live.** `common/components/` (not a pod; pods never import pods; the router imports them).
- **Forcing a route error in tests.** A separate test file mocks one scene module to throw (`vi.mock` is hoisted per file, so it cannot share `router.test.tsx`).
- **Sheet close ring.** `SheetContent` gains an optional `closeButtonClassName` merged with `cn()`; the shell passes the `sidebar-ring` variant, the primitive default stays generic.
- **Edge coverage (spec-less fallback).** DEMO-03 and DEMO-04 were not classified by the edge probe; this plan covers their automatable part (class and behaviour assertions) and the rest is the manual UAT of 06-12.
