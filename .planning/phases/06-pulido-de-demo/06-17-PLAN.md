## Assumptions and decisions (explicit, for the user to review)

- **One consolidated human checkpoint (orchestrator note 6).** The orchestrator asked for `checkpoint:human-verify` tasks recorded in a UAT file; `workflow.human_verify_mode` is `end-of-phase`, so every browser-only check is folded into this single blocking checkpoint at the very end, which costs one pause for the whole phase. The re-check of a fixed screen is not a second pause: Task 3 writes it into `06-UAT.md` as a `Re-check …` test with `result: [pending]`, and `/gsd-verify-work 06` resumes that file at its first pending test. It is the same file the end-of-phase harvest of `<human-check>` blocks would write, so this plan carries no `<human-check>` and the phase has a single human record.
- **Measured values the gate can check (DEMO-03, DEMO-04, DEMO-05).** Task 1 writes `06-UAT.md` with every matrix and focus cell set to `pending` and every time set to `seconds: pending`. The presenter replaces each one with the measured `scrollWidth/clientWidth`, `visible` / `not visible` or the seconds, either in the file or in the reply. The Task 3 UAT gate fails until every cell holds a value and every row is `pass` or `fixed`. This is the mandatory recorded result for what jsdom cannot see: real overflow at 360, 768 and 1280, painted focus and the stopwatch. The automated half is the 06-11 guards (360 px risk points, plus width classes per breakpoint at 768 and 1280).
- **Fix, don't defer, the layout and keyboard issues (D-12, D-13).** Each one gets the smallest change in its component plus a guard that fails without it; only issues that are not layout or keyboard defects (for example an Ollama run over 120 s on the presenter's machine) become gaps for `/gsd-verify-work`, with `mock` as the documented fallback.
- **S10 in the real app.** The production build has no way to force a route render error (search params degrade leniently). S10's content, focus and axe are covered by `route-error.test.tsx` (06-11, 06-12); its layout is the same card and button classes as S9, so the S9 check at each viewport stands for S10's layout. Recorded as such in `06-UAT.md`.
- **The executor seeds the default project, never resets it.** The user runs `--reset` before the timed runs, as the README says.
- **Edge coverage (spec-less fallback).** DEMO-03 was not classified by the edge probe (flagged assumption: this manual pass plus the 06-11 guards are its evidence); DEMO-05 boundary and precision are the two backstop truths above.
