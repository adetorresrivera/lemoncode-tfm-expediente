## Phase Goal

**As a** presenter, **I want to** have seeded data, a README and a responsive, accessible UI, **so that** the full demo runs in under 2 minutes on a clean machine.

This plan does the two cheap extras of D-20: no single request can push an unbounded body into Mongo, and a failed smoke never leaves records in the presenter's demo list.

<objective>
A JSON body limit on the applications router and `.max()` on the unbounded strings in contracts (02 WR-01), then a cleanup trap in the existing compose smoke (02 WR-02), both flipped to `fixed`.

Purpose: DEMO-05 (a clean demo list, a robust API); D-20.
Output: body limit and its test, contract bounds and tests, trap in `scripts/compose-smoke.sh`, Phase 2 dispositions.
</objective>
