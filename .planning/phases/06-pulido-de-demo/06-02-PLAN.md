## Assumptions and decisions (explicit, for the user to review)

- **Status distribution (Claude's discretion, D-04).** enviada 3, en_entrevistas 3, guardada 2, oferta_recibida 1, aceptada 1, rechazada 1, descartada 1. 3-round applications: one `en_entrevistas` (its third round in the future), the `oferta_recibida` and the `rechazada`. One-round applications: the other two `en_entrevistas` and the `aceptada`.
- **PDFs land with the plan that references them.** The two remaining PDFs are generated in Task 1, because from that commit on the full suite runs the 06-01 runner over the 12-application plan and needs every asset. Same scratch generator as 06-01, English file names (CLAUDE.md).
- **Strict options.** Only `--reset` is accepted; anything else exits 2 before any connection. This also gives a safe way to prove flag forwarding in the verify (`npm run seed -- --nope` must be rejected), so no verify ever wipes the devcontainer database, and a cheap in-image check of the D-01 command.
- **Keep-and-unmark for linked seed documents.** Rule 4 forbids deleting a linked document; the seed honours it for user applications by keeping the document and turning it into a user document. `--reset` deletes everything, links included, because that is its purpose.
- **Edge coverage (spec-less fallback).** DEMO-05 concurrency is resolved for the interrupted case (truth above). Flagged assumptions, not resolved: two seed runs started in parallel are not supported (the presenter runs one at a time); a crash in the instant between an application insert and its mark leaves one unmarked record that only `--reset` removes.
- **Test bucket wipe.** The `--reset` integration case empties `tfm-assets-test`; API test files run one at a time (`fileParallelism: false`), so no other file has objects there at that moment.
