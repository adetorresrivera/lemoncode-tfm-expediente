## Assumptions and decisions (explicit, for the user to review)

- **D-08 wins over the old DEMO-01 wording (orchestrator note 1).** The requirement and ROADMAP SC1 are reworded in this plan; the user sees the change at plan review.
- **Strict options.** Only `--reset` is accepted; anything else exits 2 before any connection. This also gives a safe way to prove flag forwarding in the verify (`npm run seed -- --nope` must be rejected), so no verify ever wipes the devcontainer database.
- **Keep-and-unmark for linked seed documents.** Rule 4 forbids deleting a linked document; the seed honours it for user applications by keeping the document and turning it into a user document. `--reset` deletes everything, links included, because that is its purpose.
- **Edge coverage (spec-less fallback).** DEMO-05 concurrency is resolved for the interrupted case (truth above). Flagged assumptions, not resolved: two seed runs started in parallel are not supported (the presenter runs one at a time); a crash in the instant between an application insert and its mark leaves one unmarked record that only `--reset` removes.
- **Test bucket wipe.** The `--reset` integration case empties `tfm-assets-test`; API test files run one at a time (`fileParallelism: false`), so no other file has objects there at that moment.
