# Phase 6 — UI Design Contract

> Visual and interaction contract for the polish phase: Spanish not-found and route-error screens, the skip link and sidebar focus fix in the shell, the in-flight dialog close behaviour, the error-icon / off-scale spacing sweep, the responsive (360 / 768 / 1280 px), keyboard, labelling, live-region and contrast (AA, light and dark) acceptance rules, and the display constraints on the seeded demo data and the README screenshot. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Sources, in order of authority: `docs/DESIGN.md` (literal, locked), `06-CONTEXT.md` D-11…D-13, D-18, D-19, D-22 (locked), the approved Phase 2-5 UI contracts as precedent (`02-UI-SPEC.md`, `05-UI-SPEC.md`, `05-UI-REVIEW.md`), then the code in `apps/web/src`. Nothing here overrides those documents except where an **Amendment** says so, with the measured reason.
>
> **No new product capability, no new screen except the two error screens of D-18, no new design token, no new font size, no new weight, no new shadcn block, no new runtime dependency.** The typography scale is exactly four sizes and two weights with no exceptions: the three inherited off-scale items (wordmark, `ThemeToggle`, `AiMark`) are mapped onto it by Amendments A8-A10. The only new package (`axe-core`, devDependency, test only) belongs to the plan, not to this contract.
>
> Out of scope (do not design): Kanban / dashboard («Tablero» keeps «Próximamente»), onboarding or "load demo data" button in the UI, a language switch, a print stylesheet, offline mode, a cookie or about page, theme store desync (01 WR-03, deferred), per-tab re-rendering of 04 WR-01/WR-02.

## Typography

Exactly four sizes (11, 14, 16, 28 px) and two weights (400, 600), with **no exceptions**. This phase adds none, and removes the three off-scale items that earlier phases inherited (Amendments A8-A10).

| Role | Size | Weight | Line Height | Where |
|------|------|--------|-------------|-------|
| Body | 16px (`text-base`) | 400 | 1.5 | Paragraphs, field text, error-screen body |
| Label | 14px (`text-sm`) | 600 for labels, buttons, badges, links, nav items; 400 for hints, errors, live-region lines | 1.5 | Buttons, skip link, nav items, live lines |
| Eyebrow | 11px (`text-[11px]`) | 600 | 1.5 | `uppercase tracking-[0.08em] text-muted-foreground`: «Expediente» above every `h1`, including the error screens |
| Heading | 16px (`text-base`) | 600 | 1.2 | `font-serif`: section and card `h2` |
| Display | 28px (`text-[28px]`) | 600 (`h1`) / 400 (wordmark) | 1.2 | `font-serif`: `h1` of every screen, including «No encontramos esta página» and «Algo ha fallado»; brand wordmark «Expediente» (sidebar, sheet title and mobile bar, A8) at weight 400 |

Rules:
- Weights 400 and 600 only. **Amendment A3:** `NAV_ITEM_CLASS` `font-medium` (500) → `font-semibold`.
- **No inherited exceptions remain.** Mapping of the three items that used to sit outside the scale:
  - Brand wordmark «Expediente» → Display role: `font-serif text-[28px] leading-[1.2] font-normal` in the desktop sidebar, the Sheet title and the mobile bar (was 24 / 24 / 20 px). It fits: about 130 px wide against 224 px of sidebar and a 56 px bar (`h-14`, 34 px line box) next to the 44 px menu button at 360 px. Weight 400 vs the `h1`'s 600 keeps the logotype from reading as a second heading. Amendment A8.
  - `ThemeToggle` items → Label role (14 px, 600, inherited from the `toggle` primitive); no `text-xs`. Layout in Interaction §2. Amendment A9.
  - `AiMark` → Eyebrow size with weight 600: `text-[11px] font-semibold` (was `font-bold`, 700). Amendment A10.
- Containers that hold user text keep `min-w-0` + `break-words` (already widespread); any new container that renders user text follows the rule.

**Destructive rules (Amendment A1, supersedes the «inherited exemption» of `05-UI-SPEC.md` and the Phase 2 / 4 precedent).** `text-destructive` on `bg-card` is **2.83:1 in dark** (3.10 on `bg-background`, 2.35 on `bg-accent` hover), below the 3:1 non-text floor, measured 2026-11-06. Therefore **no icon or text anywhere is tinted `text-destructive`**. Destructive appears only as `bg-destructive` with `text-destructive-foreground` (7.40 / 5.80) and as the `aria-invalid:border-destructive` field border (border, not text; the message beside it carries the meaning). Sweep: remove `text-destructive` from the 11 `CircleAlert` error icons (`request-status.tsx`, `upload-dialog.tsx`, `document-picker.tsx`, `interview-dialog.tsx`, `detail-states.tsx` ×2, `document-list.component.tsx`, `edit-states.tsx` ×2, `form-field.tsx`, `list-error.tsx`) so they inherit `text-foreground`, and from the `Trash2` of the application delete trigger (`delete-dialog.tsx`). An icon always sits next to its message text, so colour was never the only signal.

**Sidebar surfaces (Amendment A5, new).** `ring` (navy `#1f3a5f`) on `sidebar` (`#182b47`) is **1.24:1 in light**: today the focus ring is invisible on the mobile menu button, the Sheet «X» and the theme toggle, and the nav links have no focus style at all. Every focusable element on a `bg-sidebar` surface (desktop `aside`, mobile header bar, Sheet content) uses `focus-visible:ring-2 focus-visible:ring-sidebar-ring` (gold on sidebar: 6.32 light, 9.63 dark) and `outline-none`. Concretely: nav `Link`s, the «Abrir menú» button, the `ThemeToggle` items, the Sheet close button (`focus:ring-sidebar-ring`), the skip link is **not** on the sidebar (it floats over the page, uses `ring`).

## Layout and Interaction Contract

### 1. Not-found and route-error screens (D-18)

Both render the same card, `section` with `mx-auto flex w-full max-w-xl flex-col items-start gap-4 rounded-md border border-border bg-card p-6`:

```
┌────────────────────────────────────────────┐
│ EXPEDIENTE                       (Eyebrow)   │
│ No encontramos esta página       (h1, serif) │
│ La dirección no existe o ya no está …        │
│ [← Volver a Mis candidaturas]  (primary)     │
└────────────────────────────────────────────┘
```

- `h1` carries `tabIndex={-1}` and takes focus on mount (the screen replaced the content the user was on; screen readers announce the heading). Not-found is a plain `section`; the route-error card has `role="alert"`.
- Route error: `CircleAlert` (`size-4`, `text-foreground`, `aria-hidden`) before the body, buttons in `flex flex-wrap gap-2`: «Volver a cargar la pantalla» (`Button` default, `RotateCcw`, calls `reset()` then `router.invalidate()`), then «Volver a Mis candidaturas» (`Button variant="outline" asChild` over a plain `<a href="/applications">`, so it works even when router state is broken; a full reload is acceptable there).
- Not-found action: `Button asChild` over TanStack `Link to="/applications"`, `ArrowLeft` icon.
- Placement: `defaultNotFoundComponent` and `defaultErrorComponent` on the router render inside the shell's `<main>` (sidebar and header visible). If the root route itself fails, the root `errorComponent` renders the same card standalone: `min-h-screen bg-background text-foreground flex items-center justify-center p-4`, no shell.
- Both set `document.title` as in Copywriting.
- 360 px: the card is `w-full`, buttons `w-full sm:w-auto`, text wraps; no horizontal scroll.

**Focal points (visual hierarchy, inherited, stated so they are protected).** E2 error screens: the `h1` (28 px serif) on the card, the single default Button as secondary anchor. E3 list: the card title (serif `h2`, first card in the sorted list) is the anchor, the status badge on each card is the secondary anchor; «Añadir candidatura» is the page's one default Button. E4 detail: the `h1` (job title) is the anchor, the status badge beside it the secondary. E5 form: the `h1` is the anchor, the offer-text area of the AI panel the secondary (first field the eye lands on, directly above the form). No phase 6 change may promote a control or an icon above these; the accent stays on the single default Button per view.

### 2. Shell (`layouts/app-layout.tsx`)

- **Skip link** is the first child of the layout: `<a href="#main-content">`. Hidden until focused (`sr-only focus:not-sr-only`), then `focus:fixed focus:left-4 focus:top-4 focus:z-50 focus:inline-flex focus:h-11 focus:items-center focus:rounded-md focus:border focus:border-input focus:bg-card focus:px-4 focus:text-sm focus:font-semibold focus:text-foreground focus:ring-2 focus:ring-ring`. Activating it calls `preventDefault()` and focuses `<main id="main-content" tabIndex={-1} className="… outline-none">` (no `#main-content` appended to the URL, no router interference).
- Sidebar and mobile bar focus: Amendment A5 (colour section). Nav links: `outline-none focus-visible:ring-2 focus-visible:ring-sidebar-ring`.
- Touch targets: «Abrir menú» `size-11` (was `size-9` via `size="icon"`), nav links and ThemeToggle items `min-h-11`.
- Wordmark: `font-serif text-[28px] leading-[1.2] font-normal` in the three places (Typography rules, A8).
- **ThemeToggle layout (A9).** Each of the three items is a column: 16 px icon above a 14 px / 600 label («Sistema», «Claro», «Oscuro»), `ITEM_CLASS = "h-auto min-h-11 flex-1 flex-col gap-1 px-1 py-1"` (text size and weight come from the `toggle` primitive; no `text-xs`). Measurement: the narrowest container is the 224 px desktop sidebar (256 px minus `p-4`; the Sheet at 360 px gives 238 px), so each item is about 74 px; the longest label «Sistema» is about 51 px at 14 px / 600, plus 8 px of padding is about 59 px, leaving about 15 px free. Side by side (icon 16 + `gap-2` 8 + label 51 + padding 8 = 83 px) does not fit, which is why the layout is stacked rather than the padding squeezed. Item height is about 49 px (4 + 16 + 4 + 21 + 4), above the 44 px target. The planner verifies at 360 px (`scrollWidth <= clientWidth`, no label clipped) in the UAT pass.
- The current route's link keeps `aria-current="page"` (TanStack `Link` sets it; assert it in the test). «Tablero» stays a non-focusable `aria-disabled` span with «Próximamente».
- After choosing a link inside the Sheet the menu closes (existing). Esc closes the Sheet and focus returns to «Abrir menú» (Radix default; assert).
- Route changes: every scene sets `document.title` (list, detail, form, documents already do; the two new screens do); scenes that arrive after a mutation keep focusing their `h1` through `useArrivalNotice` (existing, unchanged).

### 3. Dialogs with an in-flight lock (D-19, 05 WR-03)

Applies to the upload dialog (**required**) and, as a one-prop change on the shared primitive, to the interview dialog («Guardando…») and the delete dialogs («Eliminando…») (**recommended**; if it expands beyond the prop, leave those three untouched and record it as known debt).

- `DialogContent` / `AlertDialogContent` gain an optional `closeDisabled?: boolean` (default `false`). When `true` the shared «X» renders `aria-disabled="true"` with `aria-disabled:opacity-50`, stays focusable (a `disabled` button would drop focus to `<body>`) and its click does nothing beyond the pod's own `onOpenChange` guard.
- Any attempt to close while locked (X click or Enter, Esc, overlay) writes the sentence from Copywriting into the dialog's existing always-mounted `role="status" aria-live="polite"` line: upload → «Cancela la subida para cerrar.»; others → «Espera a que termine para cerrar.». The line is plain `text-sm text-muted-foreground` with no icon (same slot and style as «Subida cancelada.»). It clears when the lock ends or the dialog reopens.
- Everything else about the dialogs is unchanged (`05-UI-SPEC.md` §1): «Cancelar subida» aborts, focus moved to it when the upload starts.
- **Reset on open (02 WR-03).** Every opening of the application delete dialog, the round delete dialog and the document delete dialog starts without the error of a previous attempt: the error line is empty and the focus is on the safe button («Conservar …»). Cancelling after an error and reopening shows a clean dialog.

### 4. List refetch (02 WR-04)

- The «Ninguna candidatura coincide con los filtros» and the absolute empty states render **only** from a settled successful response whose list is empty. While a request is in flight: first load (no data yet) shows the skeleton; a refetch (filters, sort, retry after error, return from a mutation) keeps the previous cards with `aria-busy="true"` on the results region and the counter keeps its previous value until data arrives. If the refetch fails the error block replaces the cards (existing). Never a flash of an empty state between data.

### 5. Responsive contract (DEMO-03, D-12)

Three verification viewports: **360 × 740**, **768 × 1024**, **1280 × 800**. ### 6. Keyboard contract (DEMO-04, D-13)

- Every interactive element is reachable and operable with Tab / Shift+Tab, Enter, Space, Esc and the arrow keys of toggle groups; no keyboard trap other than modal dialogs (focus trapped by Radix, released on close); DOM order equals visual order.
- Visible focus on every focusable element in both themes: `focus-visible:ring-2` with `ring` on page surfaces, `sidebar-ring` on sidebar surfaces (Amendment A5). No `outline: none` without a replacement ring.
- Global tab order: skip link → sidebar / menu button (nav links, theme toggle) → page content. After activating the skip link focus is on `<main>`.
- Keyboard-only demo walk (manual, recorded in UAT, both themes): list → «Añadir candidatura» → «Pegar oferta» textarea → «Autocompletar con IA» → review fields (IA marks and «Complétalo tú» reachable) → CV picker (select, «Subir nuevo») → «Guardar candidatura» → detail → «Añadir ronda» (dialog, Esc, reopen) → status select → «Descargar» → back to the list → status filter toggles → «Limpiar filtros». At every step: focus visible, nothing skipped, nothing unreachable, focus returns to the opener when a dialog closes.
- Labelling: every form control has a visible `<label>` (or, for the search field, the theme toggle and icon-only buttons, an `aria-label` / `aria-labelledby`); placeholders never replace labels; every icon-only button names its object («Eliminar {nombre}», «Quitar {etiqueta}», «Cerrar», «Abrir menú»); toggle groups have a group label; `aria-invalid` + `aria-describedby` on fields with errors (existing). Automated by axe rules `label`, `button-name`, `link-name`, `aria-*`, `landmark-*`, `heading-order`, `duplicate-id`, `html-has-lang`, `document-title`.

### 7. Live regions (DEMO-04, D-13)

Rule: a message that appears after load is announced only if its container was mounted **before** the text changed. Inventory (all exist, verify, add where missing):

| Region | Mechanism | Messages |
|--------|-----------|----------|
| Scene status line (list, documents, detail, form) | always-mounted `<p role="status" aria-live="polite">` | arrival notice («Candidatura eliminada.», «Documento subido.», «Documento eliminado.») |
| Result counter | `aria-live="polite"` | «12 candidaturas», «Sin documentos» |
| List / documents / detail / form loading | `role="status"` with sr-only text (rendered with the skeleton) | «Cargando …» |
| Block-level load errors | `role="alert"` card inserted in place of the content (announced on insertion) | existing error headings |
| Inline errors, AI result and progress, upload progress, 409 | `RequestStatus` inside an always-mounted `role="status" aria-live="polite"` container | «Analizando la oferta…», AI summary, error lines, «Subiendo el archivo…» |
| Dialog lines | always-mounted polite container above the footer | in-flight, error, close-blocked sentences |

DEMO-04's «`aria-live="polite"` on load / error / AI results» is satisfied by `role="status"` (implicit polite; explicit `aria-live="polite"` is kept wherever it is already written) for everything except the block-level load errors, which stay `role="alert"` by Phase 2 precedent (a polite region that is created together with its text is not announced). The test asserts, per message above, that its closest live ancestor is `role="status"`, `aria-live="polite"` or `role="alert"`, and that the container is in the DOM before the text.
