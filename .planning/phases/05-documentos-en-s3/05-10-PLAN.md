## Phase Goal

**As a** job seeker, **I want to** upload my CV and cover letters and attach one of each to an application, **so that** I always know which documents I sent to each company.

This gap plan closes G-05-4 (cosmetic, UAT test 4): in the upload dialog the native button «Seleccionar archivo» and its label «Ningún archivo seleccionado» look misaligned. Root cause (diagnosed in 05-UAT.md): the file input reuses the shared `Input` (`h-11`, `px-4`, `text-base`, no vertical padding); native file inputs flow their content from the top instead of centring it in a fixed height, and the `::file-selector-button` is `text-sm` with no height while the file-name text inherits `text-base`, so the two sit on different baselines near the top of the 44 px box.

<objective>
Centre the native file button and its file-name text on one baseline inside the 44 px «Archivo» control of the upload dialog, red-first through a class assertion in the pod test (Task 1, tracer); then amend the design contract in 05-UI-SPEC.md and run the full gate (Task 2). The upload dialog is the single component behind both modes (D-22), so the fix reaches /documents and the «Subir nuevo» picker of the application form (D-17) at once.

Purpose: the file control reads as one tidy line at 360 px and on desktop, so the demo of «Subir documento» looks finished.
Output: one className change, one new test, an amended UI-SPEC row and typography rule.
</objective>

## Assumptions (explicit, for the user to review)

- Class list chosen (Claude's discretion within the gap's `missing` items): add `py-2` and `text-sm` to the input, and `file:inline-flex file:h-7 file:items-center` to the native button, keeping every existing `file:` utility. This is the same pattern shadcn's canonical Input ships (`py-1` + `file:inline-flex file:h-7` in an `h-9` box); scaled to our `h-11` it gives: 44 px border box, 1 px border and 8 px padding per side, a 28 px button whose own text is centred by `items-center`, and the file-name text sharing the button's baseline because both are 14 px. The 2 px by which the 28 px button exceeds the 26 px content row fall inside the bottom padding, inside the padding box, so nothing is clipped. If the human check still sees the pair sitting low, the only follow-up to try is `py-1.5` instead of `py-2` (the button then fits a 30 px row); that is a UAT follow-up, not executor discretion.
- The file-name text drops from 16 px to 14 px. The DS (05-UI-SPEC Typography) puts button labels at 14 px and input text at 16 px; the file control is the one place where an input shows a button label beside its text, so both go to 14 px and the Typography rules get one bullet saying so. Text inputs stay at 16 px (they also keep iOS from zooming on focus; a file input opens a picker, not a keyboard).
- `requirements: [DOC-01, DOC-03]`: the dialog is the upload of DOC-01 at /documents and the «Subir nuevo» of DOC-03 in the form. DOC-02 (413/415 messages) is untouched; the error line under «Archivo» stays where it is.
- No dependency on other gap plans; every phase-5 plan (05-01..05-09) is already executed.
- docs/DESIGN.md does not pin the file-control classes (`grep -rn "file:" docs/` returns nothing at 2ff6f2a), so only 05-UI-SPEC.md is amended.
