## Phase Goal

**As a** job seeker, **I want to** upload my CV and cover letters and attach one of each to an application, **so that** I always know which documents I sent to each company.

This gap plan closes G-05-4 (cosmetic, UAT test 4): in the upload dialog the native button «Seleccionar archivo» and its label «Ningún archivo seleccionado» look misaligned. Root cause (diagnosed in 05-UAT.md): the file input reuses the shared `Input` (`h-11`, `px-4`, `text-base`, no vertical padding); native file inputs flow their content from the top instead of centring it in a fixed height, and the `::file-selector-button` is `text-sm` with no height while the file-name text inherits `text-base`, so the two sit on different baselines near the top of the 44 px box.

<objective>
Centre the native file button and its file-name text, both at 16 px, on one baseline inside the 44 px «Archivo» control of the upload dialog. Task 1 (tracer) does it red-first through a class assertion in the pod test and records the class list in the «Archivo» row of 05-UI-SPEC.md. Task 2 runs the full gate and makes the human check the condition for closing the gap, with a fallback inside this plan if the check fails. The upload dialog is the single component behind both modes (D-22), so the fix reaches /documents and the «Subir nuevo» picker of the application form (D-17) at once.

Purpose: the file control reads as one tidy line at 360 px and on desktop, so the demo of «Subir documento» looks finished.
Output: one className change, one new test, one amended UI-SPEC row, and a human check recorded in 05-UAT.md test 4.
</objective>
