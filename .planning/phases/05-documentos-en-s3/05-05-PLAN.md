## Phase Goal

**As a** job seeker, **I want to** upload my CV and cover letters and attach one of each to an application, **so that** I always know which documents I sent to each company.

This plan delivers the first half of DOC-03 in the UI: in the application form the user picks an existing CV and an existing cover letter (or none) and the save stores the links (validated by 05-03). «Subir nuevo» inside the same pickers comes in 05-06.

Task 1 builds and tests the picker inside its pod; Task 2 renders it from the form through the scene.

Purpose: the demo flow «adjuntar CV» works for documents already in the library, and the slot keeps the two pods independent (D-14).
Output: picker mode, form section, slot type, scene wiring, tests.
</objective>

## Assumptions and decisions (explicit, for the user to review)

- **Slot extended with `error` (D-14 arguments unchanged).** D-14 fixes `{ type, selectedId, onSelected }`; the slot also passes the field's first error so the picker can put `aria-invalid` and `aria-describedby` on its own select and the form's focus-first-invalid helper finds it. Without it a server 400 on a link would be invisible.
- **The slot is a required prop**, like `renderCancelLink`: a scene that forgets it is a type error, not a form that silently drops the section. The pod tests pass a test double picker (a plain select that calls `onSelected`), never the real pod.
- **Picker mode renders `DocumentPicker` directly from the container**; the generic mode keeps `DocumentUploadComponent`. 05-06 adds «Subir nuevo» and the shared dialog to the picker.
- **Loading and error keep the value.** The select renders one option whose value is the current `selectedId` with the state text, and ignores changes while `aria-disabled`, so React never resets the field.
- **Spec-less edge DOC-03 «unclassified» (flagged assumption, not resolved by the probe).** Reviewed manually: its relevant edges are covered by the truths above (missing option, failed list, unlink with «Sin …») and by 05-03 (wrong type, unknown id). Nothing else is assumed.
- **Router tests and the real picker.** From this plan the real scene renders the pickers, so router tests at `/applications/new` see `GET /api/documents` answer the mock's 404 and show the picker error state; no router test asserts on it. 05-06 adds a `GET /api/documents` default to `mock-fetch.ts` and the end-to-end router test.
