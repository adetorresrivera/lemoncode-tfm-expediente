## Phase Goal

**As a** job seeker, **I want to** upload my CV and cover letters and attach one of each to an application, **so that** I always know which documents I sent to each company.

This gap plan closes G-05-4b (cosmetic, UAT test 4 re-test of 2026-11-06). After 05-10 the native «Seleccionar archivo» control reads as a small outline button, but the user asked: «move the button outside the white square and make it a bit bigger so it matches the other buttons». Root cause (diagnosed in 05-UAT.md): the button is the native `::file-selector-button`, a pseudo-element drawn inside the `<input type="file">`. That input reuses the shared `Input` box (`border border-input bg-card h-11 px-4`), so the button always renders inside the bordered square, and 05-10 sized it as outline/sm (32 px high, 12 px padding) while every other dialog button is `h-11`. This is a design change request, not a defect. G-05-4 itself is resolved by 05-10 and is not re-planned here.

<objective>
Remove the box from the upload dialog's file input (no border, transparent fill, no horizontal padding, at least 44 px high) and size the native file-selector button like the dialog's other outline buttons (`h-11`, `px-4`), with the error state moved onto the button border. Task 1 (tracer) does it red-first through the class assertion test in the pod test file and records the class list in the «Archivo» row of 05-UI-SPEC.md. Task 2 runs the full gate (typecheck, tests, lint) and makes the human re-test of 05-UAT test 4 the condition for closing the gap, with one in-plan fallback for vertical alignment. The upload dialog is the single component behind both modes (D-22), so the change reaches /documents and the «Subir nuevo» dialog of the application form (D-17) at once.

Purpose: the file control looks like the rest of the dialog's buttons and no longer sits inside a white box, so the «Subir documento» demo looks finished at 360 px and on desktop.
Output: one className change, one rewritten test, one amended UI-SPEC row, and a human check recorded in 05-UAT.md test 4.
</objective>

## Assumptions (explicit, for the user to review)

- «Outside the white square» means the input box disappears, not that the button moves into a separate element: the native `::file-selector-button` cannot leave its `<input>`, and 05-UI-SPEC forbids hiding the native control behind a custom button. Removing the input's border, fill and horizontal padding (`border-0 bg-transparent px-0`) leaves the button on the dialog background with the file name as plain text beside it, which is what the user sees as «outside the square». `shadow-none` from the diagnosis list is not added: the shared Input has no shadow, so it would be a no-op token.
- «A bit bigger so it matches the other buttons» is matched to «Descartar subida», the dialog's outline button: `h-11` (44 px) and `px-4` (16 px), with the outline look already in place from 05-10 (border, `bg-background`, `rounded-md`, `shadow-xs`, Label role, accent hover). `py-2` from the Button default size is not carried over: on a 44 px border box `file:items-center` already centres the 20 px label line, and `justify-center`, `gap-2`, `whitespace-nowrap` and `shrink-0` stay out for the reasons recorded in 05-10 (single text child, the engine keeps the label on one line).
- Height arithmetic: the input has 0 border and 0 padding, so its content row holds the 44 px button exactly. `h-auto min-h-11` replaces the fixed `h-11` so the control is never shorter than 44 px and grows instead of clipping if an engine's line box comes out taller (Chrome sets `overflow: hidden` on file inputs). The file name (16 px, 24 px line) shares the label's baseline inside the 44 px row, so nothing overflows; F1 in Task 2 covers an engine that does not centre it.
- Focus indicator: the input keeps the shared Input's `focus-visible:ring-2 focus-visible:ring-ring` and `rounded-md`, so Tab onto «Archivo» draws the project ring around the whole control (button plus file name), as on every other field. The ring is not moved onto the button: that would need overriding the shared ring and would leave two focus styles to reconcile, with no gain the user asked for.
- Error state: with no input border, `aria-invalid:border-destructive` from the shared Input paints nothing, so `aria-invalid:file:border-destructive` turns the button border to the DS destructive colour instead. The error line under «Archivo» (FormField `CircleAlert` + text) and the focus move are unchanged.
- Width at 360 px: the dialog content is about 294 px wide (328 px minus `p-4` and the 1 px border). The button takes about 170 px with its 12 px margin, so the native control cuts the file name with its own ellipsis, which 05-UI-SPEC's long-text row already accepts. `w-full min-w-0` keeps the control inside the dialog, so there is no horizontal scroll. Hovering or clicking the empty area to the right of the name still opens the picker and highlights the button; that is native behaviour of a full-width file input and is kept.
- Human verify mode is `workflow.human_verify_mode` = `"end-of-phase"` (`.planning/config.json`). The executor writes the SUMMARY with G-05-4b pending; the plan closes only on the UAT re-test of test 4.
