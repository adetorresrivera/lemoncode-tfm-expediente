## Phase Goal

**As a** job seeker, **I want to** upload my CV and cover letters and attach one of each to an application, **so that** I always know which documents I sent to each company.

This plan completes DOC-03 in the UI: inside the application form the user uploads a new CV or cover letter without leaving the form, and it is selected at once. It also proves the demo step «adjuntar CV» end to end through the router.

<objective>
Move the upload dialog of 05-04 to `components/upload-dialog.tsx`, open it from a «Subir nuevo» button in each picker (picker mode: fixed type, specific title), merge the uploaded document into the picker and select it; add the `GET /api/documents` default to `mock-fetch` and the router end-to-end tests.

Purpose: the form flow of the demo no longer depends on visiting `/documents` first.
Output: one dialog for both modes, «Subir nuevo», isolation and end-to-end tests.
</objective>

## Assumptions and decisions (explicit, for the user to review)

- **Dialog extraction is a move, not a rewrite.** The 05-04 dialog and form move unchanged to `components/upload-dialog.tsx`; the only new input is `fixedType` (picker mode: no Tipo, specific title). Both modes share one instance per container (D-22).
- **The new option goes first.** The API lists newest first, so putting the just-uploaded document at the top matches what a reload would show; the label comes from the upload response through `documentLabel`.
- **D-21 test through the router.** Discarding the form is a navigation; the test proves no request removes the document and that the next form lists it (the list handler of the mock returns the uploaded document after the POST).
- **Initial focus.** Picker mode opens on Archivo (first tabbable, no Tipo); generic mode keeps Tipo first (UI-SPEC §1 keyboard order).
