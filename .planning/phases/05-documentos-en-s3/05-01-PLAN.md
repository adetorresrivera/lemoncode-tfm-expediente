## Phase Goal

**As a** job seeker, **I want to** upload my CV and cover letters and attach one of each to an application, **so that** I always know which documents I sent to each company.

This plan is the phase's API tracer: the thinnest production-quality path from a multipart `POST /api/documents` through the body cap, the parser, the contracts schema, the signature check, the S3 key slug, the real Silo bucket and the Mongo `documents` collection, and back as a `Document`. Later plans widen it without changing this architecture: read, download and delete (05-02), link validation (05-03), the upload dialog on `/documents` (05-04, the web tracer), the form pickers (05-05, 05-06), the detail section (05-07), the library screen (05-08) and the phase gate (05-09).

Task 1 is the tracer (one PDF, real Silo test bucket, real Mongo `tfm_test`); Task 2 covers every limit of the same path.

## Assumptions and decisions (explicit, for the user to review)

- **D-05 and D-08 land together in the tracer (both rated costly in CONTEXT, settled there, no checkpoint).** `fileName` is required (RESEARCH Open Question 1, RESOLVED: no tolerance, no data exists). The list item is `documentSchema.extend({ usedBy: z.int().min(0) })` in contracts (planner's discretion in D-08); the web view models never derive from it.
- **Validation order (planner's discretion, D-01).** `parseBody` failure → 400. Then the text fields (`documentInputSchema.safeParse`) and the file presence are checked together and reported in one 400 whose details have the `z.flattenError` shape (`{ formErrors: [], fieldErrors: { file?, type?, name?, version? } }`), so the web maps them like every other endpoint. Then size (413), then the file name (400 when empty after sanitizing) and the signature (415). Messages: 413 «El archivo supera 5 MB.», 415 «Solo se admiten archivos PDF o DOCX.», missing file «Elige un archivo», malformed body «Formulario no válido».
- **S3 key slug (D-07 read literally plus «no ..»).** The allowed set is `[a-z0-9._-]`; runs of `-` and runs of `.` collapse to one, and `-` and `.` are trimmed from both ends of the stem, so `..` can never appear. Cut at 100 characters including the forced extension.
- **fileName length.** The contract caps it at 255 (zod counts UTF-16 units). The sanitizer keeps the extension (from the last dot, when it is at most 10 characters) and cuts the stem so the result fits, never splitting a surrogate pair.
- **DOCX detection reads the central directory, not the local headers** (RESEARCH Pattern 2, Pitfall 2: streamed ZIPs have no compressed size in the local header). ZIP64 sentinels and any structural inconsistency return null → 415. Nothing is decompressed. Real Word/LibreOffice files (Assumption A1) are checked once in the manual UAT (05-09).
- **Two size checks.** `bodyLimit` at `UPLOAD_BODY_LIMIT_BYTES` stops the body before it is buffered (rejects on `Content-Length`, aborts a chunked body at the first byte over the cap), then `file.size > DOCUMENT_MAX_BYTES` is the exact check (RESEARCH Pattern 1, Pitfall 5). `app.request` only exercises the chunked branch; the `Content-Length` branch is covered by one test over a real socket (`serve` on port 0).
- **Real Silo only for the tracer row.** The tracer uses `createDocumentStorage` against the dedicated bucket `tfm-assets-test` (created with `ensureBucket`, cleaned with the recorded keys), mirroring `tfm_test` for Mongo; every other row uses `fakeStorage()` (RESEARCH Validation Architecture, Claude's discretion in CONTEXT).
- **Compensation is tested at service level** with a repository whose `insert` rejects and a storage whose `delete` rejects too: the service must reject with the very insert error (identity) and the fake must hold no object (D-04, D-30).
- **CSRF (RESEARCH Open Question 2, RESOLVED).** `hono/csrf` is not adopted; accepted low risk T-05-09.
- **Spec-less edge probes lifted here:** DOC-01 empty, encoding and concurrency (API part); DOC-02 empty, encoding and concurrency (API part). The browser-side concurrency rows (abort during upload, 413 seen by a real browser) are in 05-04.
