## Phase Goal

**As a** job seeker, **I want to** upload my CV and cover letters and attach one of each to an application, **so that** I always know which documents I sent to each company.

This plan is the phase's web tracer: the thinnest production-quality path from the new `/documents` route, through its scene and the `document-upload` pod (button, dialog, TanStack form, hook with `AbortController`) and `http-client` with a `FormData` body, to `POST /api/documents` (built in 05-01), and back into the page as «Documento subido.». The library list on the same page comes in 05-08; the picker mode of the same pod in 05-05 and 05-06.

<objective>
Wire one path end to end: route `/documents` (lenient `type` search) → `DocumentListScene` (header) → `DocumentUploadContainer` in generic mode → `DocumentUploadComponent` (button, live line, dialog with the upload form) → `useDocumentUpload` (`uploadDocument`, abort) → `request()` with `FormData`. Task 1 is the tracer; Task 2 covers validation, server errors, the uploading state, cancel, close guards, prefill and focus on the same dialog.

Purpose: proves `FormData` through the shared client, the dialog form and the route/scene/pod composition before the pickers and the list depend on them.
Output: `FormData` support in `http-client`, `DOCUMENT_TYPE_LABELS`, the `document-upload` pod in generic mode, the `/documents` route and scene, regenerated route tree, tests.
</objective>

## Assumptions and decisions (explicit, for the user to review)

- **Container props (Claude's discretion in D-22).** Generic mode: `initialType?` (the active `/documents` filter, else CV) and `onUploaded?({ id, type })`. Picker mode (05-05): `type`, `selectedId`, `onSelected`, `error?`. One component, one dialog.
- **Route search.** Derived from `documentQuerySchema` field by field and lenient (`.catch(undefined)`), like `listSearchSchema` for `/applications`: a bad `?type=` degrades to Todos instead of an error page (D-26).
- **Uploading state (D-20 locked: «botón deshabilitado»).** The submit is `disabled` while uploading and focus moves to «Cancelar subida» at that moment so it never drops to `<body>` (UI-SPEC §1). The handler also returns early.
- **Server field errors through `onSubmitAsync`** (copy of `useApplicationForm`): 413 and 415 map to the Archivo field, a 400 maps each named field (type, name, version, file) to «Revisa este campo.», everything else is a dialog-level message. Never the server's message text.
- **Inner form isolation from day one.** The dialog form's `onSubmit` calls `preventDefault()` and `stopPropagation()` (RESEARCH Pattern 7) although on `/documents` there is no outer form; the test that proves it inside the application form is in 05-06.
- **Live line placement.** The container renders the opener and its always-mounted `role="status" aria-live="polite"` line; the scene places the container in its header and the line spans the full header width under the h1 row (`basis-full`), with no visual height when empty.
- **No list yet.** Until 05-08 the page has no library list; `onUploaded` is already part of the contract and tested, and the scene passes a handler that 05-08 extends.
- **Spec-less edge probes lifted here:** DOC-01 concurrency and DOC-02 concurrency, browser side, both as backstops (real browser behaviour, checked in the 05-09 UAT).
