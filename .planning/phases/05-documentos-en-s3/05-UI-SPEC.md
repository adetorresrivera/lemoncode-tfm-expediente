# Phase 5 — UI Design Contract

> Visual and interaction contract for the documents feature: the upload dialog and the CV / cover-letter pickers in the application form (`apps/web/src/pods/document-upload`, `application-edit`), the «Documentos» section of the detail aside (`application-detail`), and the new `/documents` screen (`pods/document-list`, `scenes/document-list.scene.tsx`). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Sources, in order of authority: `docs/DESIGN.md` (literal), `05-CONTEXT.md` decisions D-14…D-29 (locked, restated only where the executor needs the visual consequence), `05-RESEARCH.md` Patterns 7-10, then the Phase 2 and Phase 4 UI contracts as precedent, then the code already in `apps/web/src`. Nothing here overrides those documents. Prose is English; every string in a `Copy` cell is Spanish exactly as it ships. No new design token, no new size, no new weight, no new npm dependency.
>
> Out of scope (do not design): version grouping of the library (LIB-01), AI CV suggestion (LIB-02), a progress bar, drag-and-drop, preview/inline viewing of the file, renaming or replacing an uploaded file.

## Layout and Interaction Contract

### Where the focal point sits

- **`/documents`**: the eye lands on the `h1` «Documentos», then the primary «Subir documento»; inside the list, the only coloured element is the neutral «En uso» badge, which is deliberately more distinctive than the type badge (bordered card surface vs filled muted) because it is the hook of the rule-4 demo.
- **Form**: the new «Documentos» section is the last card before the actions row; no emphasis beyond the section heading. The single primary action stays «Guardar candidatura».
- **Detail**: the aside card is secondary to «Editar»; the only accent is the «Descargar» link text.

### 1. Upload dialog (one component, two modes — D-17, D-18, D-19, D-20, D-22)

One `UploadDialog` instance per `DocumentUploadContainer`, controlled (`closed | open`). Chrome is the Phase 4 `Dialog`. Remount the dialog **form** on every opening so each opening starts empty (Pattern 7).

```
┌ DialogContent ─────────────────────────────────── [X] ┐
│ Subir documento                           (h2, serif)   │
│ Sube un PDF o un DOCX. Se guarda en tu biblioteca...    │
│ <form noValidate class="flex flex-col gap-4">           │
│   Tipo            [ CV | Carta ]      (generic mode only)│
│   Archivo *       [Elegir archivo  CV-2026.pdf]         │
│     PDF o DOCX, hasta 5 MB.                             │

│                                         [ Ej.: v3  ]    │
│   <div role="status" aria-live="polite"> line </div>    │
│   [Subir documento]  [Descartar subida] (mobile: stacked)     │
```

Fields, in DOM and visual order:

| Field | Control | Default | Notes |
|-------|---------|---------|-------|
| Tipo | `ToggleGroup type="single" variant="outline"` with items CV, Carta, `className="grid w-full grid-cols-2"`, item treatment as Phase 4 (`h-auto min-h-11 w-full justify-center whitespace-normal px-2 text-center leading-tight`, selected = `bg-primary text-primary-foreground`) | The active `/documents` filter (`cv` / `carta`), else `cv` | **Generic mode only.** An empty value from Radix (pressing the active item) is ignored so a value is always selected. Named by a visible «Tipo» label via `aria-labelledby`. In picker mode the type is fixed by the picker and this control is not rendered. |
| Archivo | `Input type="file" accept=".pdf,.docx"` with its box removed, input classes `h-auto min-h-11 w-full min-w-0 border-0 bg-transparent px-0` (no border, no fill, no side padding, at least 44 px high), native button styled as the dialog's outline buttons («Descartar subida», `Button variant="outline"` at `h-11`) with `file:mr-4 file:inline-flex file:h-11 file:cursor-pointer file:items-center file:rounded-md file:border file:border-border file:bg-background file:px-4 file:text-sm file:font-semibold file:text-foreground file:shadow-xs file:transition-colors hover:file:bg-accent hover:file:text-accent-foreground aria-invalid:file:border-destructive` (file-button margin `file:mr-4`, Phase 6 Amendment A2; amended 2026-11-06, UAT G-05-4 and G-05-4b: the button sits on the dialog background, outside any box, at the 44 px height of the other dialog buttons; the file name is plain Body-role text beside it; the error state shows on the button border and the shared Input's focus ring outlines the control; the shared Input is unchanged) | none | `aria-required="true"`, ` *`, `aria-describedby` = hint and error. Do not hide the native control behind a custom button: the native filename text is the confirmation of the choice and keeps keyboard and screen-reader behaviour. |
| Nombre | `Input` | empty; prefilled when a file is chosen (below) | `maxLength={120}`, `autoComplete="off"`, ` *`. |
| Versión | `Input`, value rendered `font-mono tabular` | empty | `maxLength={40}`, `autoComplete="off"`, ` *`, placeholder «Ej.: v3». Required (D-18). |

- At `sm` (640 px) and up, «Nombre» and «Versión» share a row (`grid gap-4 sm:grid-cols-3`, «Nombre» `sm:col-span-2`); below that every field is full width and stacked. «Archivo» always has its own row.
- **Name prefill (D-18)**: on choosing a file, if «Nombre» is empty, set it to the file name without extension, trimmed, cut to 120 characters. If «Nombre» still holds the previous automatic prefill (the user has not edited it), replace it with the new one; a name the user typed is never overwritten. The «Nombre» input does not take focus (the user is still on «Archivo»).
- **Client validation (D-19)** runs on submit, then re-validates on change; it uses `documentInputSchema` for the text fields plus extension (`.pdf`/`.docx`, case-insensitive) and `file.size <= DOCUMENT_MAX_BYTES` (imported from `@tfm/contracts`) for the file. File errors are attached to «Archivo»; text errors to their fields; error markup is the `FormField` line (`CircleAlert` + `text-sm text-foreground`). On a failed submit focus moves to the first `[aria-invalid="true"]` control in DOM order. A zero-byte file passes the client and ends as the server's 415 («Solo se admiten archivos PDF o DOCX.»).
- **Server errors**: 413 and 415 are shown **under «Archivo»** (field error, `aria-invalid`) and focus moves to the file input; the dialog stays open and every typed value is kept. 400 field details map to their field with «Revisa este campo.». `NETWORK_ERROR` and any other failure render in the dialog's always-mounted live region above the footer as `RequestStatus kind="error"`. Errors are cleared when the user starts a new submit, changes the file, or reopens the dialog.
- **Uploading (D-20)**: «Subir documento» becomes «Subiendo…» and is **`disabled`** (locked D-20: «botón deshabilitado»; the submit handler also returns early). A disabled button that held focus would drop it to `<body>`, so at the moment the upload starts focus is moved programmatically to «Cancelar subida» (stable, active, in the same footer); this replaces the `aria-disabled` pattern of Phase 4 for this one button. The live region (`role="status" aria-live="polite"`, always mounted) shows `RequestStatus kind="loading"` «Subiendo el archivo…». The secondary button changes from «Descartar subida» to **«Cancelar subida»** and stays active: it aborts the `fetch` (`AbortController`), the dialog **stays open** with every value kept, and the live region says «Subida cancelada.» as a plain `text-sm text-muted-foreground` line (no icon; `RequestStatus` has no neutral kind). While uploading, the X, Esc and overlay are ignored (same rule as Phase 4 «Guardando…»); «Cancelar subida» is the only way out. Fields are not disabled. No spinner beyond the `LoaderCircle` already inside `RequestStatus`; no progress bar.
- **Success (D-17)**: the dialog closes; in picker mode the new document enters the picker's list and is selected (`onSelected(id)`); in generic mode `onUploaded(document)` fires. Focus returns to the opener (`onCloseAutoFocus` pointing at the opener ref, as `interview-dialog.tsx`: «Subir nuevo» or «Subir documento»). The container's always-mounted `role="status" aria-live="polite"` line next to the opener announces **«Documento subido.»** (`RequestStatus kind="success"`, cleared after `SUCCESS_VISIBLE_MS`, 5 s). In the form the line sits directly under the picker's select; on `/documents` it sits under the page header.
- **Isolation (D-17, verified in Research Pattern 7)**: the inner `<form onSubmit>` calls `event.preventDefault()` **and** `event.stopPropagation()`; every other button the picker renders inside the application `<form>` («Subir nuevo», «Reintentar») is `type="button"`. The dialog form never submits the application.
- **Keyboard order**: generic mode: Tipo (one tab stop, arrows inside) → Archivo → Nombre → Versión → «Subir documento» → «Descartar subida» / «Cancelar subida» → X (last in DOM, top-right visually). Picker mode skips Tipo. Initial focus is the first tabbable element (Tipo in generic mode, Archivo in picker mode). Esc closes unless uploading. Visible focus is the project ring everywhere.
- **Buttons**: submit `type="submit" variant="default" className="h-11 w-full sm:w-auto"`; secondary `type="button" variant="outline" className="h-11 w-full sm:w-auto"`. Footer `flex flex-col-reverse gap-2 sm:flex-row sm:justify-end` (primary on top on mobile).

Why «Descartar subida» and not Phase 4's «Descartar cambios»: nothing has been saved and no record is being edited, so the noun is the upload; the same noun names the in-flight abort («Cancelar subida»). Every dialog CTA is a specific verb + noun (no bare «Cancelar»). It is a deliberate, local choice, not drift.

Elige uno que ya tengas o sube uno nuevo.», then the two pickers stacked (`gap-4`; CV first, then carta). Present in create and edit. Anatomy of one picker (`DocumentPicker`, `div flex flex-col gap-1`):

- `NativeSelect` `h-11`, `sm:flex-1`, with `Label htmlFor`. Options: «Sin CV» / «Sin carta» first (value `""`, maps to `null`; this is how the user unlinks), then the documents of that type, newest first as served, each with the document label. - **After upload success**: the select shows the new document, the live line says «Documento subido.», focus returns to «Subir nuevo». The upload is independent of the application (D-21): discarding the application changes never removes it from the library.

### 4. `/documents` screen (D-26 … D-29)

Scene `document-list.scene.tsx` composes: header, `DocumentUploadContainer` (generic mode, owns the «Subir documento» button, dialog and its «Documento subido.» line), and `DocumentListContainer` (filter, results, delete). Route validated with `documentQuerySchema` (`?type=cv|carta`; absent = Todos). Filter changes use `navigate({ search, replace: true })`.

**Header** (`flex flex-col gap-4`): eyebrow «Expediente»; row with `h1` «Documentos» (Display, `tabIndex={-1}`) and the counter (`aria-live="polite"`, Label size, `text-muted-foreground`; it keeps the previous number while a refresh is in flight); primary Button «Subir documento» (`Upload` icon, `h-11 w-full sm:w-auto`). From `sm`: `sm:flex-row sm:items-end sm:justify-between`. The upload container's live line («Documento subido.») is mounted directly under the header (always mounted, zero height when empty) and is followed by the list pod's own live line («Documento eliminado.»); the page therefore has two small, adjacent, polite regions, each announcing a different event.

**Filter**: directly under the header, `div role="group" aria-label="Tipo de documento" className="flex flex-col gap-1"`; Eyebrow label «Tipo», then `ToggleGroup type="single" variant="outline" spacing={2}` with Todos, CV, Carta (items `h-11 px-4 text-sm font-semibold`, selected `data-[state=on]:bg-primary data-[state=on]:text-primary-foreground data-[state=on]:border-primary`). Empty value from Radix is ignored (Todos cannot be unselected). No card around the filter (only three options).

**Results region**: `section aria-label="Resultados" tabIndex={-1}`. Exactly one of:
- **Loading (first load)**: `div role="status"` with sr-only «Cargando documentos…» and 3 skeleton rows (`aria-hidden`) with the geometry of a real row. A refresh (filter change, upload, retry) keeps the previous rows, sets `aria-busy="true"` on the region and does not flash a skeleton.
- **Error**: `role="alert"` card (`rounded-md border border-border bg-card p-6 flex flex-col items-start gap-4`) with `CircleAlert`, heading, body by error code, outline Button «Reintentar» (`RotateCcw`). Retry moves focus to the results region.
- **Empty (no filter)**: the same card chrome with `<p className="text-muted-foreground">Aún no has subido ningún documento. Empieza subiendo tu CV.</p>`. No second button: the header's «Subir documento» is the one action (avoids a second opener for the same dialog).
- **Empty by filter**: card with «Aún no has subido ningún CV.» / «Aún no has subido ninguna carta.» and an outline Button «Ver todos los documentos» (sets the filter to Todos).
- **Populated**: `ul aria-label="Documentos" className="flex flex-col gap-4"`, one `li` per document in the API's order (`createdAt` desc), no pagination.

**Document row** (`li > article`, `flex flex-col gap-4 rounded-md border border-border bg-card p-4 lg:p-6 sm:flex-row sm:items-start sm:justify-between`):

- Left block `min-w-0 flex flex-1 flex-col gap-2`: `h2` name (Heading, `font-serif text-base font-semibold leading-[1.2] break-words`); meta row `flex flex-wrap items-center gap-x-4 gap-y-2` with, in order: type badge, version (`font-mono tabular text-sm`, sr-only prefix «Versión: »), `<time dateTime={iso} className="text-sm text-muted-foreground">` with `formatDate` (sr-only prefix «Subido: »), size (`font-mono tabular text-sm text-muted-foreground`). - **Actions** `flex shrink-0 items-center gap-2` (below the content on mobile, right-aligned from `sm`): «Descargar» = `Button asChild variant="outline" className="h-11"` wrapping `<a href="/api/documents/{id}/download" download aria-label="Descargar {nombre}">` with `Download` icon and visible text; «Eliminar» = `Button type="button" variant="ghost" className="size-11" aria-label="Eliminar {nombre}"` with `Trash2` (`aria-hidden`, `strokeWidth={1.5}`). Always visible, always enabled (D-29: the rule-4 demo needs a clickable delete on a linked document).

**Delete flow (D-29)**: one controlled `DocumentDeleteDialog` (`AlertDialog`) for the whole list, same structure as `interview-delete-dialog.tsx`.
- Initial focus on «Conservar documento». Esc and overlay click close it, except while deleting.
- Confirm «Eliminar documento» (`destructive`, `h-11`). While deleting: «Eliminando…», both buttons `aria-disabled="true"`, every close request ignored.
- **409**: the dialog **stays open**; the error line (`RequestStatus kind="error"`, in an always-mounted `role="status" aria-live="polite"` container above the footer) reads «Este documento está vinculado a alguna candidatura. Desvincúlalo antes de eliminarlo.». The confirm button becomes available again. Nothing is removed from the list.
- Other failure (network, 5xx): «No se pudo eliminar el documento. Inténtalo de nuevo.» in the same slot; dialog stays open.
- **Success**: dialog closes, the row is removed from the list (the mutation response is the new truth), counter updates, the list pod's live line announces «Documento eliminado.» (`RequestStatus kind="success"`, 5 s). Focus moves programmatically to the **results region** (`tabIndex={-1}`), the one stable element left, because the deleted row's buttons no longer exist.
- The `AlertDialogDescription` interpolates user text (name up to 120, version up to 40): `break-words`, and the content keeps `max-h-[calc(100dvh-2rem)] overflow-y-auto` so it stays inside a 360 px viewport.

**Upload from `/documents`**: «Subir documento» opens the dialog in generic mode with «Tipo» preselected to the active filter (or CV). On success the list reloads (scene refresh signal, D-27). If the uploaded type differs from the active filter (the user changed «Tipo» in the dialog), the scene sets the filter to the uploaded type (`replace: true`) so the new row is visible; announcement is still «Documento subido.». Focus returns to «Subir documento».

**Keyboard order** (`/documents`): sidebar/menu → «Subir documento» → filter (one tab stop, arrows move) → for each row: «Descargar» → «Eliminar {nombre}» → next row. Delete dialog traps focus; upload dialog traps focus (see §1).

### 6. Responsive (from 360 px, no horizontal scroll)
