## Assumptions and decisions (explicit, for the user to review)

- **Package legitimacy (blocking).** The package audit flags `playwright` and `mermaid` as `[SUS]`, reason `too-new` only: their *latest* releases are days old (2026-11-05 and 2026-11-03). Both are official, widely used and have no install scripts. The plan pins older releases: `playwright@1.56.1`, the version of the local image and of the Phase 6 browser pass, and `mermaid@11.17.2`, published 2026-08-25 and the newest 11.x. Both are installed with `--ignore-scripts`, inside a throwaway container only. Task 1 stops for the human in every mode (`gate="blocking-human"`). `js-tiktoken` (07-02) is OK and needs no checkpoint.
- **Automated browser, not Claude in Chrome.** The Playwright path is already proven on this stack (Phase 6 and research). Claude in Chrome is the fallback only if the human rejects the packages in Task 1. In that case the human picks it in the resume signal, and the same shots and viewports are taken by hand-driven automation.
- **Provider for the AI-marks shot.** Ollama first, because the image then shows «Nimbo Software», which matches the live demo and its plan C. The wait is up to 120 s. If the Ollama shot fails twice, the executor recreates only the app with `LLM_PROVIDER=mock`, takes the shot, then runs `docker compose up -d app` to restore Ollama. The runner prints the provider, and the SUMMARY records it so 07-04 words plan C correctly (under mock the image shows «Lumen Analytics»). D-17 allows mock for determinism.
- **The user's data is left alone.** Captures only read and navigate; the form is never submitted. If the list is empty, the executor runs the normal `docker compose exec app npm run seed`, never `--reset`. The presenter reseeds with `--reset` himself on the morning of the defense.
- **`docs/img/application-list.png` is not refreshed.** D-17 makes this optional. The file was taken on 2026-11-07 in 06-17 with the same rules (1280 × 800, DPR 1, light, seeded list), and the seed has not changed since.
- **Where the scripts live.** The two in-container scripts sit under `docs/presentacion/`, which ESLint and Prettier ignore, as RESEARCH recommends: they import `playwright`, which is not installed in the repository. The runner lives in `scripts/` next to `compose-smoke.sh`.
- **No one-way doors.** Committed PNGs can be replaced or deleted; the runner is dev-only. All reversible.
