## Phase Goal

**As a** job seeker, **I want to** paste an offer and get a reviewable draft of the application form, **so that** I fill an application in seconds without losing anything I already typed.

This plan expands the tracer's LLM layer: the real Ollama and OpenAI-compatible calls replace the 502 bodies left from Phase 1, behind one helper that owns the timeout budget and the single retry. After it, the same «Autocompletar con IA» click works against the local `gemma4:e2b`.

<objective>
Implement `callStructured` (D-21: one `AbortSignal.timeout(LLM_TIMEOUT_MS)` combined with the request signal, two attempts only for unparseable or schema-invalid output, fixed error messages) and the real `extractStructured` of the Ollama and OpenAI-compatible providers on top of it, with request-body and parsing tests on a stubbed `fetch`.

Purpose: AI-02 and AI-03 live here; the subtle part is the interplay of budget, retry and abort reasons, so it is written and tested once.
Output: structured-call.ts with tests; real provider bodies; llm.client.test.ts with request/parse tests replacing the Phase 1 always-502 assertions.
</objective>

## Assumptions (explicit, for the user to review)

- `options.num_ctx: 8192` is sent to Ollama next to `temperature: 0` (RESEARCH Pitfall 1, approved by the user on 2026-10-31). The SUMMARY records it as a spec addition; it is a code constant, so `.env.example` does not change.
- `strict: true` is added inside `json_schema` for the OpenAI-compatible provider (RESEARCH Q3, recommendation accepted). The top-level `$schema` key emitted by `z.toJSONSchema` is left out of the OpenAI request body only, since Ollama accepted it live and an OpenAI-compatible vendor may reject unknown keywords (RESEARCH A1). The cloud path is covered by stubbed-`fetch` tests only: there is no key in the devcontainer.
- A transport failure or a non-2xx answer is not retried: D-21 limits the retry to unparseable or schema-invalid output.
- A client cancel ends as 502 `LLM_ERROR` on the server; the browser has already dropped the request, so nobody reads it. Timeout and cancel are told apart by `timeout.aborted`, never by the error's name (RESEARCH Pitfall 6).
- The mock provider stays unchanged (it already returns a schema-valid object after 300 ms; plan 03-01 left it compatible with the new options parameter).
- Spec-less edge probes lifted here: AI-02 boundary, AI-02 concurrency, AI-03 idempotency, AI-03 concurrency.

Per D-21, D-02, AI-03 and RESEARCH Pattern 3:

1. `callStructured` creates `const timeout = AbortSignal.timeout(args.timeoutMs)` once and `const signal = args.signal ? AbortSignal.any([timeout, args.signal]) : timeout`.
2. Loop over at most two attempts. Each attempt awaits `args.send(signal)` inside a try; on rejection throw `ApiError(504, "LLM_TIMEOUT", "La IA ha tardado demasiado")` when `timeout.aborted`, otherwise `ApiError(502, "LLM_ERROR", "El modelo no está disponible")` (no retry; decide by the signal you created, not by the rejection's shape or name).
3. A content of null, or text that a private `parseJson(text): unknown` cannot parse (try/catch around `JSON.parse`, the caught error is discarded so its message never travels), or a value for which `args.schema.safeParse` fails, moves to the next attempt; a success returns `result.data`.
4. After the second failed attempt throw `ApiError(502, "LLM_ERROR", "La respuesta del modelo no es válida")`. Before that throw, if `timeout.aborted` became true during the second attempt's wait, the timeout rule of step 2 already applied.
5. No logging in this file. Tests in `structured-call.test.ts` with real timers and small budgets, a `z.object({ a: z.string() })` schema and a `vi.fn` send, covering every behavior above.
