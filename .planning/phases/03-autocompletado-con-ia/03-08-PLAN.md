## Phase Goal

**As a** job seeker, **I want to** paste an offer and get a reviewable draft of the application form, **so that** I fill an application in seconds without losing anything I already typed.

This plan finishes the «Pegar oferta» panel (AI-05): the user knows how much text the AI will accept (one pair of limits shared with the API through contracts), can stop a slow local model, and never loses control of the form while it runs.

<objective>
Export the offer text limits from contracts and use them in the API schema and the panel: length gate, counter, limit hints and the D-18 length message (D-19, Task 1); then the read-only textarea and disabled trigger while analysing (D-20) and «Cancelar análisis» with the cancelled state and the single focus move (D-05, D-18, Task 2).

Purpose: a CPU model can take tens of seconds; the panel must stay honest and interruptible during the demo.
Output: contracts constants, hook guard and cancel, panel states, flow tests.
</objective>

## Assumptions (explicit, for the user to review)

- The contracts constants land in this plan, next to their only web consumers (D-19: «limits come from offerExtractRequestSchema or constants exported next to it»). The schema keeps the same bounds, so the API tests of plans 03-01 and 03-03 pass unchanged; the fixtures test of plan 03-03 validates through `offerExtractRequestSchema` and does not need the constants.
- The counter counts `draft.length` (what `maxLength` limits); the button gate counts `draft.trim().length` (what the API validates). Both are UTF-16 code units, the unit of `String.length` and of Zod's string checks.
- «Has llegado al límite …» replaces «Pega al menos …» when both could apply (they cannot: the limit implies at least 50 characters).
- The trigger is disabled while analysing so the textarea (read-only) and Cancel stay visible; the status region outside the collapsible keeps announcing either way.
- Spec-less edge probes lifted here: AI-05 idempotency and concurrency; AI-01 boundary and encoding (web part).
