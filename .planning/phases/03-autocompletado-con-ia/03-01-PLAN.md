## Phase Goal

**As a** job seeker, **I want to** paste an offer and get a reviewable draft of the application form, **so that** I fill an application in seconds without losing anything I already typed.

This plan is the phase tracer: the thinnest production-quality path from the «Pegar oferta» panel through `POST /api/offers/extract`, the extract service and the swappable `LlmClient` (the existing mock provider answers it end to end) back into the form. Later plans widen each layer without changing this architecture: real Ollama/OpenAI calls with timeout, retry and the call options (03-02), normalization, cancel propagation to the model call, fixtures and logging (03-03), salary, currency and missing fields (03-04), «IA» and «Complétalo tú» marks (03-05), tags (03-06), `offerText` (03-07), contracts limits, counter and cancel (03-08), phase gate and the manual model test (03-09).

<objective>
Wire one path end to end: `offersRoutes` mounted by `createApp` when `deps.llm` exists → `createExtractService` with the literal system prompt → the swappable `LlmClient` (existing mock provider) → `extractOffer` in the web pod → `mergeExtractionIntoForm` (fill-only-empty for the six text/enum fields) → `OfferPanel` with loading, success and error copy. Task 1 is the tracer; Task 2 covers the validation boundaries, the errors, the wait and the edit mode on the same path.

Purpose: a dead end in the dependency injection of the LLM, in the programmatic form write, or in the panel placement surfaces after one commit, not after nine plans.
Output: offers route and service with route tests (including the verbatim-prompt check); `AppDeps.llm`; panel, hook, mapper and API call in the edit pod with flow tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → POST /api/offers/extract | Untrusted offer text (up to 20,000 characters, possibly with prompt injection) enters the API |
| API → LLM | The text is forwarded to a model whose answer is untrusted |
| API response → form | AI values are written into the form the user saves |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-03-02 | Information disclosure | offers route / app.onError logging | high | mitigate | No logging in the route; the only log is `app.onError`'s `err.message`, and every error on this path is a ZodError, SyntaxError or ApiError with fixed text; the sentinel log test lands in plan 03-03 |
| T-03-03 | Tampering | prompt injection inside the pasted offer | medium | mitigate | The model output is validated against `offerExtractionSchema`, the endpoint persists nothing and has no tools, and the merge only fills empty fields the user reviews before saving |
| T-03-SC | Tampering | npm installs | high | mitigate | No package is installed in this plan; lockfile unchanged |
