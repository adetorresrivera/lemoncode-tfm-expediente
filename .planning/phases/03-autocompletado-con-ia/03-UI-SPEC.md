## Spacing Scale

Declared values (multiples of 4). Same scale and same section card rhythm as the existing form sections (`rounded-md border border-border bg-card p-4 lg:p-6`, `gap-4` between children).

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | `gap-1` between a control and its hint/missing line; badge/label gap inside chips |
| sm | 8px | `gap-2` label ↔ «IA» badge; button ↔ button; icon ↔ text in `RequestStatus`; chip icon gap |
| md | 16px | Panel padding (`p-4`); `gap-4` between textarea block, actions and status region |
| lg | 24px | Panel padding from `lg` (1024 px) up (`lg:p-6`); `gap-6` between the panel and the next form section (inherited from the form's `gap-6`) |
| xl | 32px | not used |
| 2xl | 48px | not used |
| 3xl | 64px | not used |

Exceptions:
- Touch targets: buttons are `h-11` (44px) like every other form control; the collapsible trigger row is `min-h-11`.
- Fixed element sizes inherited from DESIGN.md: «IA» badge `h-5` (20px), chip `h-7` (28px), chip AI icon `size-3` (12px, the lower bound allowed by D-14, chosen to stay on the 4px grid).
- «IA» badge horizontal padding `px-1.5` (6px, not a multiple of 4): inherited verbatim from the DESIGN.md §Marca IA class string (`inline-flex h-5 items-center rounded-sm bg-brand-navy px-1.5 ...`). Justification: at an 11px label, 4px padding is too tight and 8px too loose for a 20px-high mark; the DS fixed 6px. Scoped to `AiBadge` only; nothing else may use half-step spacing.
- Textarea height: `min-h-40` (160px) at 360 px width and up, `resize-y`.

| Accent (10%) | `bg-primary` / `bg-brand-navy` | #1f3a5f / #afc2dd (primary), #1f3a5f / #34557f (brand-navy) | See reserved list |
| AI-missing | `border-brand-gold`, `bg-ai-missing-bg`, `text-brand-gold-ink` | #b08d3c, #fbf6e9, #7a5410 / #c9a961, #2a2416, #d4b56a | Missing-field highlight only |
| Destructive | `text-destructive` | #9b2c2c / #b23a3a | Only the `CircleAlert` icon inside `RequestStatus` kind `error` (existing behaviour). No destructive action exists in this phase |

Accent reserved for (exhaustive):
1. The «Autocompletar con IA» button (`variant="default"` = `bg-primary text-primary-foreground`).
2. The existing «Guardar candidatura» button.
3. The «IA» badge (`bg-brand-navy text-brand-parchment`).
4. The `Sparkles` icon of AI-proposed tag chips (`text-primary`).
5. Focus ring (`ring-ring`, inherited).

Rules:
- `brand-gold` is a border colour only. Text on the gold treatment uses `text-brand-gold-ink` (DESIGN.md: gold never as small text). Value text typed in a missing field stays `text-foreground`.
- Status colours (`status-*`) are never used for AI marks.
- Contrast measured on the token pairs (AA = 4.5:1 text, 3:1 non-text):

| Pair | Light | Dark |
|------|-------|------|
| `text-brand-parchment` on `bg-brand-navy` («IA» badge) | 10.19 | 5.59 |
| `text-brand-gold-ink` on `bg-card` («Complétalo tú») | 6.66 | 8.45 |
| `text-foreground` on `bg-ai-missing-bg` (typed value) | 14.55 | 12.28 |
| `text-primary` on `bg-card` (chip sparkle) | 11.30 | 9.22 |
| `border-brand-gold` vs `bg-card` | 3.07 | 7.43 |
| `border-brand-gold` vs `bg-ai-missing-bg` | 2.90 | 6.85 |

  The light-theme gold border sits at 2.90–3.07, i.e. at the edge of 3:1 for non-text UI. This is acceptable only because the border is **never the sole cue**: the «Complétalo tú» line (6.66:1) carries the meaning, and when the field is focused the visible indicator is the focus ring (`ring-ring`, 2px), which does not depend on the border colour. Do not drop the help line. Dimension 3 should treat this as a documented, mitigated edge, not a defect.

## Panel Layout and Interaction Contract

### Focal point

- **Create screen** (`/applications/new`): the focal point is the open «Pegar oferta» panel, at the top of the form, and its primary button «Autocompletar con IA» (navy `bg-primary` on the card, the first strong-contrast element the eye meets). «Guardar candidatura» is the form's primary action, at the bottom.
- **Edit screen** (`/applications/$id/edit`): the panel is collapsed, so the focal point is the form's first section; «Guardar candidatura» is the primary action.

### Placement and anatomy

`OfferPanel` is the first element inside the `<form>` in `application-edit.component.tsx`, before `JobSection`, same card chrome as the other sections (`section` with `aria-labelledby`, `rounded-md border border-border bg-card p-4 lg:p-6`, `flex flex-col gap-4`). Both `ApplicationCreate` and `ApplicationEditForm` render it; the container passes `defaultOpen = (mode === "create")`.

```
┌ section (card) ──────────────────────────────────────────┐
│ h2 > [CollapsibleTrigger]  Pegar oferta           [v]    │  trigger row, min-h-11, full width
│ ┌ CollapsibleContent ─────────────────────────────────┐  │
│ │ Label  Texto de la oferta                           │  │
│ │ ┌ Textarea ───────────────────────────────────────┐ │  │
│ │ └─────────────────────────────────────────────────┘ │  │
│ │ hint (left)                         1.234 / 20.000  │  │
│ │ [✦ Autocompletar con IA]  [Cancelar análisis]       │  │
│ └─────────────────────────────────────────────────────┘  │
│ <div role="status" aria-live="polite">  status line </div>│  OUTSIDE the content, always mounted
└──────────────────────────────────────────────────────────┘
```

- The trigger is a native `button` inside the `h2` (heading stays a heading; the button is the toggle). Full-width row, `flex items-center justify-between`, text `font-serif text-base font-semibold`, `ChevronDown` 16px `strokeWidth={1.5}` on the right, rotated 180° when open (`data-[state=open]:rotate-180`, `transition-transform motion-reduce:transition-none`), `focus-visible:ring-2 focus-visible:ring-ring`, `rounded-sm`.
- The status region is **outside** `CollapsibleContent` (Radix unmounts closed content) and always mounted, so announcements are never lost if the user collapses the panel. It renders nothing visible when empty (`min-h-0`).
- The textarea draft text is **state of the container/hook**, not of the textarea component, so collapsing and re-opening keeps what was typed.
- Edit mode: collapsed by default; textarea is prefilled with the stored `offerText` (empty if null) when opened (D-09).
- Textarea: `Label` + `htmlFor`, `maxLength` and the 50 minimum from the contracts constants (D-19), `aria-describedby` = hint id (when shown) + counter id, `className="min-h-40 resize-y"`. Pressing Enter inserts a newline; it never submits the form.
- Hint row: `flex items-start justify-between gap-2`; hint `text-sm text-muted-foreground` left, counter `font-mono tabular text-sm text-muted-foreground` right, `shrink-0`. The counter is **not** a live region (it would announce on every keystroke).
- Actions row: `flex flex-col gap-2 sm:flex-row`. Both buttons `type="button"` (never submit the form), `h-11 w-full sm:w-auto`. The AI button carries `<Sparkles aria-hidden="true" />` before the label (16px, `strokeWidth={1.5}`, via Button's built-in svg sizing).
- Single-primary-action resolution (flagged in CONTEXT.md §specifics): DESIGN.md explicitly makes both buttons `primary`. The contract: «Autocompletar con IA» is `variant="default"` and is the primary action **of its panel**; «Guardar candidatura» remains the primary action **of the form**. They are not visible together as competing calls to action on a 360 px screen while the panel is open (the form's sections sit between them), and in edit mode the panel is collapsed. No third `default` button is allowed in the form.

### Panel states

| State | Trigger | Textarea | AI button | Cancel button | Status region |
|-------|---------|----------|-----------|---------------|---------------|
| Idle, too short (< 50 trimmed) | — | editable | `aria-disabled="true"`, click ignored, `opacity-50`; `aria-describedby` = hint id | hidden | empty |
| Idle, ready (≥ 50 trimmed) | enabled | editable | enabled | hidden | empty (or the last result message) |
| Analysing | disabled (panel stays open) | `readOnly` (+ `bg-muted`), keeps `text-foreground` | `aria-disabled="true"` + `LoaderCircle` is NOT inside the button; label unchanged | visible, `variant="outline"` | `RequestStatus kind="loading"` «Analizando la oferta…» (spinner `animate-spin motion-reduce:animate-none`) |
| Success | enabled | editable, kept as typed | enabled (re-analysis allowed, D-11) | hidden | `RequestStatus kind="success"` with the summary; panel stays open; **focus does not move** (D-12) |
| Error | enabled | editable | enabled = the retry affordance (no separate «Reintentar») | hidden | `RequestStatus kind="error"`, one message per code; form stays fully editable |
| Cancelled | enabled | editable | enabled | hidden | neutral `<p class="text-sm text-muted-foreground">` with «Análisis cancelado.»; no icon, no destructive colour |

- Use `aria-disabled` rather than `disabled` for the AI button (same pattern as the existing save button): it stays in the tab order so keyboard and screen-reader users reach it and hear the reason through `aria-describedby`. The click/keypress handler returns early when the state is disabled.
- Cancel: calls `abort()`; **focus moves to the AI button** (the Cancel button unmounts, so this is the one programmatic focus move in the panel).
- Navigating away or unmounting aborts the in-flight request silently (no state update, no message).
- An error or cancelled message stays until the next action replaces it. A successful save clears the success/summary message together with the marks (D-17).
- The form (everything outside the panel) is never disabled, `aria-busy`-ed or overlaid while analysing (D-20).

### «IA» badge on fields (AI-07)

- Rendered by `FormField` in the label row: `<div class="flex items-center gap-2">` with the `Label` followed by `AiBadge`. The badge is **outside** the `<label>` element so the control's accessible name stays «Puesto», not «Puesto IA».
- `AiBadge` markup: `<span id="{id}-ai" class="inline-flex h-5 items-center rounded-sm bg-brand-navy px-1.5 text-[11px] font-bold tracking-wide text-brand-parchment"><span aria-hidden="true">IA</span><span class="sr-only">Rellenado por la IA</span></span>`.
- `controlProps` adds `{id}-ai` to `aria-describedby` while the badge is shown, so the control announces «Rellenado por la IA».
- Applies to the fields that can be AI-filled: Puesto, Empresa, Ubicación, Modalidad, Seniority, Tipo de contrato, Salario mínimo, Salario máximo, Moneda. It never appears on tag-group legends (D-14), status, dates, URL or notes.
- The badge disappears on the first `onChange` of that field, even if the value ends up identical (D-13). No transition, no animation.
- Appears in the same render that applies the merge; no staggered reveal.

### Missing-field treatment (AI-08)

- Applies to Puesto, Empresa, Modalidad, Seniority when still empty after a merge.
- Control (`Input` / `NativeSelect`): add `border-brand-gold bg-ai-missing-bg` through `className` (tailwind-merge resolves against the base `border-input bg-card`). Keep the base focus ring (`focus-visible:ring-2 focus-visible:ring-ring`); on focus the ring is the indicator, the gold border may be overridden by `focus-visible:border-ring`.
- Help line under the control, same slot and spacing as `hint`: `<p id="{id}-missing" class="text-sm font-semibold text-brand-gold-ink">Complétalo tú</p>`, added to the control's `aria-describedby`.
- Precedence: a validation error on the field wins. While `error` is defined, render neither the gold classes nor the «Complétalo tú» line (`aria-invalid:border-destructive` stays in charge). This avoids two competing messages on a required field after a failed submit.
- Removed as soon as the field is no longer empty and not restored if the user clears it again; it only returns after a later analysis leaves the field empty (D-16).
- A field cannot show both marks: filled → «IA», empty → «Complétalo tú».
- Because focus does not move after an analysis, the missing fields are also named in the status-region sentence («Te falta completar: …»), so screen-reader users learn about them without scanning the form.

### AI tag chip (D-14, D-15)

- `TagChip` gains an optional boolean prop (suggested name `aiSuggested`); no other variant changes. When true and the chip is the static/removable variant: render `<Sparkles aria-hidden="true" strokeWidth={1.5} className="size-3 shrink-0 text-primary" />` **before** the label span, and `<span className="sr-only">(propuesta por IA)</span>` **after** the label span (outside the truncating span, so truncation never clips it). Chip height (`h-7`), border, background and text stay as they are; the soft/dashed variant keeps its dashed border.
- The remove button keeps `aria-label="Quitar {label}"` (no mention of AI).
- Mark lifetime: the whole session until the chip is removed or the form is saved; a chip removed and re-added by hand has no mark (keyed by `tagKey`).
- Tag-group legends (eyebrow) get no badge.
- Screen-reader reading of a marked chip: «React (propuesta por IA)».

### Keyboard order and focus

Tab order: panel trigger → textarea → «Autocompletar con IA» → «Cancelar análisis» (only while analysing) → the form's first field → … → «Guardar candidatura». Space/Enter on the trigger toggles. Visible focus everywhere is the project ring (`focus-visible:ring-2 focus-visible:ring-ring`). Programmatic focus moves in this phase: exactly one (after Cancel, to the AI button). Success and error never move focus.

### Responsive (from 360 px, no horizontal scroll)

- Panel and all children `min-w-0`; textarea `w-full`; the hint row wraps (`flex-wrap`) if hint and counter do not fit one line at 360 px.
- Buttons stack full-width below `sm` (640px) and sit inline from `sm`.
- Status text wraps (`RequestStatus` already `flex-wrap`); long error strings never overflow.
- Badge sits to the right of its label and never wraps beneath it at 360 px: labels in this form are short («Salario máximo» is the longest).

### Motion

Only two animated things: the loading spinner and the trigger chevron. Both honour `motion-reduce`. No fade/slide on marks or messages.

## UI Considerations

Empty/error/success **copy** lives in the Copywriting Contract above; this table covers state coverage and references it.

Probe run 2026-10-31 over 3 surfaces (OfferPanel, merged form fields, AI tag chips): 22 applicable considerations, all resolved (21 explicit, 1 backstop), 0 unresolved. Rows below group them by category.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Offer textarea (create mode, nothing typed) | ✅ covered | Button is `aria-disabled`, hint «Pega al menos 50 caracteres» is shown, counter reads «0 / 20.000». |
| empty | Extraction result with no new data | ✅ covered | Shows «No hemos encontrado datos nuevos en la oferta. Completa el formulario a mano.» plus the missing-fields sentence; no marks are added. |
| loading | Analysis in flight | ✅ covered | «Analizando la oferta…» in a polite live region, textarea `readOnly`, Cancel visible, rest of the form editable; merge reads form values at response time (D-20). |
| error | Timeout, LLM error, network, validation | ✅ covered | One message per code in the live region (see Copywriting rows); AI button stays enabled to retry; form never blocked. |
| partial | Extraction fills some fields and leaves others empty | ✅ covered | Filled fields show «IA»; empty relevant ones (Puesto, Empresa, Modalidad, Seniority) show gold border + «Complétalo tú»; empty irrelevant ones (Ubicación, contrato, salary) get no highlight. |
| populated | Re-analysis on a partly filled form | ✅ covered | Only still-empty fields are filled; marks accumulate; `missingFields` recalculated; user-typed values untouched (D-11). |
| overflow | Offer text of 20.000 characters / paste beyond the limit | ✅ covered | `maxLength` truncates silently; at the limit the hint «Has llegado al límite de 20.000 caracteres.» appears and the counter reads «20.000 / 20.000»; textarea scrolls internally, `resize-y`. |
| long-text | Long tag labels or long extracted title | ✅ covered | Chips keep `truncate` + `title`; the sr-only «(propuesta por IA)» sits outside the truncated span; inputs scroll their text. |
| zero-one-many | Pluralisation of the success summary | ✅ covered | Singular/plural copy rows above (1 campo / N campos, 1 etiqueta / M etiquetas). |
| concurrency | Double-click on the AI button, cancel then immediately re-run, navigate away mid-request | ✅ covered | Click ignored while analysing (`aria-disabled`); cancel aborts and returns focus to the AI button; unmount aborts silently with no state update. |

| overflow | AI tag chips (many tags in a group) | ✅ covered | Chips wrap onto new lines (existing `flex flex-wrap gap-2` in `tag-group-input.tsx`); the count is capped by `MAX_TAGS` from contracts; no horizontal scroll at 360 px. |
| long-running | Local Ollama on CPU taking tens of seconds (up to the 90 s budget) | 🧪 backstop | Spinner + «Analizando la oferta…» + Cancel; behaviour on a 60–90 s run is verified in the manual UI pass after the dev script (D-24), not by an automated visual test. |
