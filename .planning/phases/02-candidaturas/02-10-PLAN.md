## Phase Goal

**As a** job seeker, **I want to** create, find, review and move my applications through their states, **so that** I have one reliable record of every selection process.

This plan lets the user create an application from the UI: legitimacy gate, TanStack Form install, the create path end to end and the entry points from the list.

<objective>
Gate the only new dependency of the phase with a human legitimacy check, install it pinned, and build the create path of the shared form (D-16): route `/applications/new`, edit scene, application-edit pod with the «Puesto y empresa» section, Spanish validation through the contracts schema, POST, and the landing on the new detail with a notice (D-13, APP-01). Add the «Añadir candidatura» entry points to the list (UI-SPEC A-8).

Purpose: creating applications is the first step of the demo flow; the AI panel of Phase 3 plugs into this same form.
Output: `@tanstack/react-form@1.33.5`; complete edit pod VM/mapper/hooks; create route and scene; list CTAs; detail arrival notice.
</objective>

## Assumptions (explicit, for the user to review)

- Package legitimacy (RESEARCH audit): `@tanstack/react-form` and its transitive `@tanstack/form-core`, `@tanstack/pacer-lite`, `@tanstack/store` are OK; `@tanstack/devtools-event-client` is flagged SUS (`too-new`) because its latest tag 0.5.1 was published the day of the research. The form core requires `^0.4.1`, which resolves to 0.4.4 (2026-06-19). Task 1 is a blocking human check before install; Task 2 asserts the lockfile holds 0.4.x and pins it with npm `overrides` only if it does not.
- TanStack Form validators receive the VM (strings), so the contracts schema is applied through a wrapper (VM → API draft → `safeParse` → Spanish messages) rather than passed directly (RESEARCH Decision Risk 4). The contracts message on salaryMax stays untouched; the web maps it.
- The VM, the mapper and the Spanish message table are complete in this plan; plan 02-11 only adds the Condiciones, Seguimiento and Etiquetas sections. Until then a created application uses the defaults (status guardada, no tags, no conditions).
- `offerText`, `cvDocumentId` and `coverLetterDocumentId` are sent as null on create (no inputs in Phase 2); Phase 3 adds the paste panel and Phase 5 the documents section.
- No unsaved-changes guard on «Descartar cambios» (UI-SPEC A-11).
- Navigation from the scene (plan revision 2, 2026-10-30): «Descartar cambios» and «Añadir la primera candidatura» are rendered by the pods but their targets come from the scenes through link render props (navigation seam of plan 02-08), so Task 3 also threads `renderCreateLink` through the list container and component.
