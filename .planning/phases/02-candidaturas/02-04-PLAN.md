## Phase Goal

**As a** job seeker, **I want to** create, find, review and move my applications through their states, **so that** I have one reliable record of every selection process.

This plan makes the list findable on the server: every filter and both sorts of `GET /api/applications` on real Mongo. Plan 02-05 builds the URL state and the search field in parallel.

<objective>
Implement every list filter and both sorts in the API exactly as D-03/D-04 define them (escaped regex, AND on stored keys, nulls last, no pagination per D-10), and harden the query contract so hostile or oversized queries answer 400 (APP-06, APP-08).

Purpose: finding an application among dozens is the second half of the demo flow («see it filtered»); the server is where the filter is actually applied.
Output: contracts query tightening; `applications.query.ts`, `query-input.ts`; repository, service and route wiring; real-Mongo tests.
</objective>
