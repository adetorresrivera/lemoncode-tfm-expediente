## Phase Goal

**As a** job seeker, **I want to** create, find, review and move my applications through their states, **so that** I have one reliable record of every selection process.

This plan makes the list findable on the web side: the filter state in the URL and the free-text search with «Limpiar filtros». Plan 02-04 implements the same query on the server, in parallel.

<objective>
Move the list state into URL search params with a serializer that keeps values as strings and degrades invalid values to "not applied" (D-13 as amended on 2026-10-30, APP-07), send that query to `GET /api/applications` from known keys only, and give the user the search field, «Limpiar filtros» and the empty-by-filters state (D-14, APP-05/06).

Purpose: finding an application among dozens is the second half of the demo flow («see it filtered»).
Output: router serializer + lenient schema + tests; route/scene/pod wiring; filter panel, search field and empty-by-filters.
</objective>
