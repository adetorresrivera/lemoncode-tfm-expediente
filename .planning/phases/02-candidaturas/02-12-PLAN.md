## Phase Goal

**As a** job seeker, **I want to** create, find, review and move my applications through their states, **so that** I have one reliable record of every selection process.

This plan closes the phase: editing with the same form, the «Editar» entry point and the phase gate on the production image.

<objective>
Implement `PUT /api/applications/:id` with an explicit whitelist that never touches status, history, interviews, ownership, offer text or document links (D-07, D-08, APP-13), and the edit mode of the shared form (D-16, APP-02): route, load and prefill, current status line, save back to the detail. Then run the phase gate: extend the compose smoke with a CRUD round trip and run the full suite.

Purpose: correcting a record is part of «one reliable record»; the gate proves the deliverable (`docker compose up`) carries every Phase 2 endpoint.
Output: PUT endpoint + tests; edit route, scene mode, pod edit path and states; «Editar» in the detail; compose smoke round trip.
</objective>

## Assumptions (explicit, for the user to review)

- PUT semantics (RESEARCH Q9): `offerText`, `cvDocumentId` and `coverLetterDocumentId` are not written by PUT in Phase 2 because the form has no inputs for them and the schema defaults would wipe them. Phase 3 (AI-09) and Phase 5 (DOC-03) must each move their field into the whitelist and make the form always send it; the SUMMARY records this hand-over.
- PUT always bumps `updatedAt` (a save is a modification, APP-13), even when the values are identical.
- The form edits dates at day precision, but an automatic `appliedAt` (set by the first move to enviada) is an exact instant. To keep a save from rewriting that instant, the edit save sends the stored `appliedAt` back whenever the local date in the form still equals the local date of the stored instant; only a changed date becomes local noon (Pitfall 10) and a cleared date becomes `null` (D-08).
- The edit pod keeps its own `getApplication` and its own load states (a pod never imports another pod, D-12); the states mirror the detail copy.
- The compose smoke writes one application into the compose Mongo volume and deletes it before finishing; it never runs `docker compose down -v`.
- Edge probes lifted here: APP-02 idempotency, APP-02 concurrency (backstop).
