# Phase 02 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Scope: the three business screens of the application tracker (list `/applications`, detail `/applications/$applicationId`, create/edit form `/applications/new` and `/applications/$applicationId/edit`), the common components they share (`StatusBadge`, `TagChip`, `RequestStatus`) and the seven new `ui/*` primitives. No AI panel (Phase 3), no interview rounds (Phase 4), no documents (Phase 5).
>
> Source of truth: `docs/DESIGN.md`, `docs/design/expediente.css` (identical to `apps/web/src/styles.css`, verified with `diff`), `docs/DOMAIN.md` (status mapping), CONTEXT decisions D-12..D-18 and RESEARCH Q7. This contract only adds what those leave open. Where they are silent the option that follows the DS most directly was picked and recorded under **Design Assumptions** (these are assumptions of this spec, not user decisions).
>
> Precedent: `01-UI-SPEC.md` (structure) and `01-UI-REVIEW.md` (drift to avoid, see **Phase 1 Carry-over**).

## Hard Constraints (from CONTEXT / RESEARCH, encoded below)

1. The detail page renders **no** interview-rounds and **no** linked-documents section: no heading, no empty state, no placeholder, no disabled button (D-15). Phases 4 and 5 add them.
2. Delete exists **only** in the detail, behind an `AlertDialog` (D-14, APP-03). There is no delete on cards. Documents are never deleted.
3. The edit form has **no** status selector. Only the create form has «Estado inicial» (D-07, D-16). Status changes happen only in the detail.
4. Tag input per group: Enter adds, chips are removable with `aria-label="Quitar <label>"` (D-16).
5. List states: loading skeleton, error with retry, empty, empty-by-filters («Ninguna candidatura coincide con los filtros») and «Limpiar filtros» (D-14, APP-05, APP-07).
6. Status change in the detail is optimistic, rolls back on error, announces the error, and has a single request in flight (D-15, APP-10).
7. Native `<select>` everywhere a select is needed (RESEARCH Q7). New primitives: `input`, `label`, `textarea`, `native-select`, `alert-dialog`, `collapsible`, `skeleton`.
8. Voice: Spanish, tuteo, short sentences, sentence case, no exclamation marks, no emojis.
9. Responsive from 360 px with no horizontal scroll; every flow keyboard-operable with visible focus; AA contrast in light and dark. Only DS tokens (`bg-primary`, `text-status-offer`...), never hex, never palette classes, never `dark:` variants.

## Spacing Scale

Declared values (multiples of 4, Tailwind default 4 px unit):

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px (`gap-1`, `p-1`) | Eyebrow → value gap; chip inner gap; timeline label → date gap |
| sm | 8px (`gap-2`, `px-2`) | Gap between chips, buttons in a row, badge parts; chip and toggle horizontal padding |
| md | 16px (`p-4`, `gap-4`, `px-4`) | Card padding on mobile; gap between form fields and filter controls; input horizontal padding; page gutter on mobile |
| lg | 24px (`p-6`, `gap-6`) | Card/panel padding from `lg` up; gap between sections and between page header and body |
| xl | 32px (`px-8`, `py-8`) | Page gutter from `lg` up (set by the content column) |
| 2xl | 48px | Not used |
| 3xl | 64px | Not used (`lg:pl-64` is the sidebar offset, Phase 1) |

Exceptions (all intentional, all listed so the checker does not flag them):
- Touch targets: inputs, native selects, page-level and form `Button`s are `h-11` (44 px). Chips and filter toggles are 28 px (`h-7`) and 36 px (`h-9`) tall, with 8 px between them, which is above the WCAG 2.2 AA minimum of 24 px; the remove button inside a chip is `size-6` (24 px).
- DS-defined badge values from DESIGN.md are kept: `py-0.5` (2 px) and the status dot `size-1.5` (6 px). They are not multiples of 4 on purpose: the DS is authoritative for the badge's internal geometry (assumption A-17). The timeline dot is `size-2` (8 px).
- Form column `max-w-3xl` (768 px); detail status select `sm:w-56` (224 px); content column `max-w-5xl` (1024 px, Phase 1).
- No 12 px spacing (`gap-3`, `px-3`, `py-3`) in any Phase 2 element. The generated primitives ship `px-3` in some variants: those classes are overridden (see Primitives), never relied upon.

## Typography

Exactly 4 sizes and 2 weights (400 regular, 600 semibold), the same four as Phase 1. DESIGN.md's tag text (13 px) is reconciled to the 14 px Label size (assumption A-1).

| Role | Size | Weight | Line Height | Where |
|------|------|--------|-------------|-------|
| Body | 16px (`text-base`) | 400 | 1.5 (`leading-normal`) | Input, select and textarea text (16 px also prevents iOS zoom on focus); notes and offer text; `dd` values; dialog description; empty/error body |
| Label | 14px (`text-sm`) | 400, or 600 for emphasis | 1.5 (`leading-normal`) | Form labels (600); helper and error text (400); buttons (600); status badge (600); tag chips (600); card metadata (company · location, «Actualizada …», salary); timeline label (600) and date (400); counter; filter labels; error messages |
| Eyebrow | 11px (`text-[11px]`) | 600 | 1.5 (`leading-normal`) | `uppercase tracking-[0.08em] text-muted-foreground`: page eyebrow «Expediente», `dt` labels, tag-group legends in forms and detail, «Actual» marker in the timeline |
| Heading | 16px (`text-base`) | 600 | 1.2 (`leading-[1.2]`) | EB Garamond (`font-serif`): card title (`h2`), detail section titles (`h2`), form section titles (`h2`), dialog title. Same size as Body; hierarchy comes from serif + semibold |
| Display | 28px (`text-[28px]`) | 600 | 1.2 (`leading-[1.2]`) | EB Garamond: scene `h1` on every screen (list, detail title, form title). Replaces the `text-3xl` (30 px) of Phase 1 |

Rules:
- Only `font-normal` and `font-semibold`. No `font-medium`, no `font-bold`, no `font-black`. The generated primitives ship `font-medium`: replace it (see Phase 1 Carry-over).
- Serif only on h1/h2 and card titles. Salary is the only `font-mono` text, always with `tabular`.
- Every text container that holds user text has `min-w-0` and `break-words` so a 120-character title or a URL never forces horizontal scroll at 360 px.
- Placeholder text is `text-muted-foreground` (AA on `bg-card`); a placeholder never replaces a label.

## Color

Values come from `docs/design/expediente.css`. Components reference tokens only.

| Role | Light | Dark | Usage |
|------|-------|------|-------|
| Dominant (60%) | `--background` #f6f1e6 | #11151d | Page background, text `text-foreground` |
| Secondary (30%) | `--card` #fffdf8, `--popover` #fffdf8, `--sidebar` #182b47 | #181e29, #181e29, #0c1018 | Application cards, filter panel, form sections, detail sections, dialog (`bg-popover`), skeleton blocks use `bg-muted`; sidebar from Phase 1 |
| Accent (10%) | `--primary` #1f3a5f (Oxford), `--ring` #1f3a5f | #afc2dd, #afc2dd | See reserved list below |
| Destructive | `--destructive` #9b2c2c | #b23a3a | See reserved list below |

Supporting tokens: `--border` for card, panel and divider lines; `--input` for field borders (3:1 or better against `bg-card` in both themes); `--muted-foreground` for metadata, helper text and eyebrows; `--muted` for skeletons; `--accent` for hover of ghost/outline buttons and chip remove buttons; status tokens only inside `StatusBadge` and timeline dots.

Accent (`primary`) reserved for:
1. The single `default` Button per view: «Añadir candidatura» (list), «Editar» (detail), «Guardar candidatura» (form).
2. Selected filter state: status toggles `data-[state=on]` and selected stack chips (`bg-primary text-primary-foreground border-primary` + `Check` icon), per DESIGN.md.
3. Text links: the back link, «Ver oferta original», «Reintentar» when rendered as a link (`text-primary underline underline-offset-4`).
4. Keyboard focus: `focus-visible:ring-2 focus-visible:ring-ring` (plus `focus-visible:border-ring` on fields) on every focusable element in the page body.

Destructive reserved for:
1. The confirm button of the delete dialog (`Button variant="destructive"`, white-on-red ≥ 5:1 in both themes).
2. Invalid state of a field: `aria-invalid:border-destructive` and the `CircleAlert` icon in front of an error message; the `Trash2` icon of «Eliminar».
3. **Never as text colour.** `--destructive` in dark (#b23a3a) is about 3.1:1 against the dark background, which fails AA for text. Error messages use `text-foreground` and are identified by the destructive icon plus the words, not by colour alone (assumption A-12; a token change is out of scope, flagged for Phase 6).

## Primitives and Common Components (class contract)

All classes below are the contract; tokens only. Executor post-processes generated files (see Phase 1 Carry-over).

**Field family** (`Input`, `Textarea`, `NativeSelect`):
`w-full min-w-0 rounded-md border border-input bg-card text-base font-normal text-foreground placeholder:text-muted-foreground outline-none focus-visible:border-ring focus-visible:ring-2 focus-visible:ring-ring aria-invalid:border-destructive`. Input and select: `h-11 px-4`; select adds `appearance-none pr-10` and its chevron sits at `right-4` (`size-4`, `text-muted-foreground`, `pointer-events-none`); textarea: `min-h-32 px-4 py-2`. No `shadow-xs`, no `dark:` classes, no `ring-[3px]`, no `/50` ring.

**Label**: `text-sm font-semibold leading-normal text-foreground`. Required marker: a trailing ` *` in an `aria-hidden` span; the field carries `aria-required="true"`. Forms use `noValidate` (no native English browser bubbles).

**Skeleton**: `animate-pulse rounded-sm bg-muted motion-reduce:animate-none`, `aria-hidden="true"`.

**StatusBadge**: `inline-flex items-center gap-2 rounded-sm px-2 py-0.5 text-sm font-semibold` + the status background/text pair; a `size-1.5 rounded-full` dot (status colour) and the lucide icon `size-4`, both `aria-hidden`; the visible text is the label. The badge is not interactive.

**TagChip**: base `inline-flex h-7 max-w-full min-w-0 items-center gap-1 rounded-sm border border-border bg-card px-2 text-sm font-semibold text-foreground`, label in a `truncate` span with `title={label}`.
- `soft` (group `nice_to_have`): adds `border-dashed`.
- `removable`: `pr-1` and a trailing `<button type="button" aria-label="Quitar {label}">` with `size-6 shrink-0 rounded-sm hover:bg-accent hover:text-accent-foreground focus-visible:ring-2 focus-visible:ring-ring` and an `X` icon (`size-4`).
- `selected` (filter): rendered as `<button type="button" aria-pressed>`; selected = `bg-primary text-primary-foreground border-primary` + `Check` (`size-4`); unselected hover = `hover:bg-accent`.
- `soft` and `removable` combine; `selected` is only used for stack filters.

**RequestStatus**: props `kind: "loading" | "success" | "error"`, `message`, optional `onRetry`/`retryLabel`. Renders `flex items-start gap-2 text-sm text-foreground`: `loading` = `LoaderCircle` (`size-4 animate-spin motion-reduce:animate-none`), `success` = `Check`, `error` = `CircleAlert` (`text-destructive`); the message is plain text. The container for inline (mutation) feedback is always mounted with `role="status" aria-live="polite"` and its text changes. Block-level load errors (a region or page replaced by an error) use the same markup in a bordered card with `role="alert"` (see Accessibility).

**AlertDialog**: Radix, `bg-popover text-popover-foreground border border-border rounded-md p-6 gap-4`, overlay `bg-sidebar/70` (as the Sheet in Phase 1; never `bg-black`), max width `max-w-md`, width `calc(100% - 2rem)` capped, `motion-reduce:animate-none motion-reduce:transition-none` on overlay and content. Title is Heading style; description is Body in `text-muted-foreground`; footer buttons `flex flex-col-reverse gap-2 sm:flex-row sm:justify-end` (generated shadcn order: Cancel first in DOM, so the visual reverse on mobile keeps the destructive action on top while DOM/focus order stays «Conservar candidatura» → «Eliminar candidatura»).

**Collapsible**: trigger is a full-width ghost `Button` (`justify-between h-11 px-4`) with `ChevronDown` (`size-4 transition-transform data-[state=open]:rotate-180 motion-reduce:transition-none`), `aria-expanded` provided by Radix; content is unmounted while closed.

## Layout and Interaction Contract

### Global
- Breakpoints: base (360 px minimum, mobile-first) and `sm` (640 px) and `lg` (1024 px, sidebar appears). No tablet-specific layout beyond `sm`.
- Page content column (Phase 1 contract, see Carry-over): `main` is `lg:pl-64`; the `Outlet` sits in `mx-auto w-full max-w-5xl px-4 py-6 lg:px-8 lg:py-8`.
- Scene header (all three screens): eyebrow «Expediente» (Eyebrow), `h1` (Display) with `tabIndex={-1}`, `gap-1`; header → body `gap-6`. `h1` is the only h1; sections are `h2`.
- Scenes set `document.title` to `«{h1 text} · Expediente»` (assumption A-14).
- **Primary visual anchor per screen** (the first thing the eye lands on; everything else is subordinate): list = the `h1` «Mis candidaturas» with the application cards (card title in serif + `StatusBadge`); detail = the `h1` title and the `StatusBadge` of the current status; form = the `h1` and the first section «Puesto y empresa», with the single primary «Guardar candidatura» as the closing anchor.
- Every `section` with a title uses `aria-labelledby` pointing at its `h2`.
- After a mutation that navigates (create, save, delete) or after «Descartar cambios», the destination scene focuses its `h1` once (router history state `{ focusHeading: true, notice? }`, assumption A-7). Direct loads and normal link navigation do not move focus.
- One-shot success notice: the destination scene renders an always-mounted `role="status"` line under the header; its text is set after mount: «Candidatura creada.» (after create), «Cambios guardados.» (after save), «Candidatura eliminada.» (after delete, shown in the list). The notice is captured into local state on mount and the history state is cleared with `replace: true` so a reload does not repeat it.

### 1. List — `/applications`

**Header.** Eyebrow «Expediente»; row with `h1` «Mis candidaturas» and the counter; primary Button «Añadir candidatura» (`Plus`, links to `/applications/new`, `h-11`). Base: stacked (`flex flex-col gap-4`), button `w-full`. `sm` and up: `sm:flex-row sm:items-end sm:justify-between`, button `sm:w-auto`. Counter is Label size `text-muted-foreground`, `aria-live="polite"` (it is the result-count announcement): «Sin candidaturas», «1 candidatura», «N candidaturas». It keeps the previous number while a refresh is in flight.

**Filter panel** (`div role="search" aria-label="Filtrar candidaturas"`, `rounded-md border border-border bg-card p-4 lg:p-6 flex flex-col gap-4`). Always rendered (all states). DOM order equals visual order:
1. **Buscar** — `Label` «Buscar» + `Input type="search"` (`maxLength={100}`, `autoComplete="off"`, placeholder «Puesto o empresa»), full width. Debounce 300 ms before navigating; the field keeps its own text state and is remounted with `key={clearCount}` on «Limpiar filtros» (never synced from the URL during render).
2. **Mobile disclosure** (`lg:hidden`): a plain `<button type="button" aria-expanded aria-controls="filters-extra">` ghost-styled `h-11` with `SlidersHorizontal` and the text «Filtros y orden» plus, when active, a count: «Filtros y orden (2)» (count = active dimensions among status, tags, work mode, seniority, plus 1 if sort is not the default). Open by default if any of them is active in the URL, closed otherwise. A plain button is used instead of Radix `Collapsible` because Radix sets the `hidden` attribute and Tailwind preflight enforces it with `!important`, so it could not be forced open at `lg`. The extra area is `id="filters-extra"` with `flex flex-col gap-4` when open and `hidden lg:flex` when closed.
3. **Estado** — group label «Estado» (Eyebrow) and `ToggleGroup type="multiple" variant="outline" spacing={2} aria-label="Estado"` with 7 items in the order of the enum (Guardada, Enviada, En entrevistas, Oferta recibida, Aceptada, Rechazada, Descartada), `flex-wrap`, items `h-9 px-2 text-sm font-semibold`, selected `data-[state=on]:bg-primary data-[state=on]:text-primary-foreground data-[state=on]:border-primary`. Text only (no icons). Radix gives `aria-pressed`.
4. **Stack** — group label «Stack» (Eyebrow); `ul` of `TagChip selected`-capable buttons (`aria-pressed`), `flex flex-wrap gap-2`, options from `GET /api/tags` where `group === "stack"`, order = count desc as served. Shows the first 10; if there are more, a ghost button «Mostrar todas ({n})» / «Mostrar menos» with `aria-expanded` follows. Tags selected in the URL that are not in the options (or beyond the first 10) are always rendered so they can be unselected. Tags filter is AND (D-04): a muted helper line under the chips when ≥ 2 are selected: «Solo candidaturas con todas las etiquetas elegidas.» Loading: 4 skeleton chips (`h-7 w-16`). Error: `RequestStatus error` «No se pudieron cargar las etiquetas.» + «Reintentar» (the other filters keep working). No stack tags yet: muted «Aún no hay etiquetas de stack.»
5. **Selects row** — `grid grid-cols-1 gap-4 sm:grid-cols-3`: **Modalidad** (Todas, Remoto, Híbrido, Presencial), **Seniority** (Todos, Junior, Mid, Senior, Lead), **Ordenar por** (Última actualización, Fecha de envío). Native selects with visible labels.
6. **Footer** — when any of text, status, tags, work mode, seniority is set, or sort is not the default: ghost Button «Limpiar filtros» (`RotateCcw`) right-aligned (`flex justify-end`). It resets everything including sort and goes to `/applications` with `replace: true`.

Every filter change is `navigate({ search, replace: true })`; Back leaves the list instead of replaying changes.

**Results region** (`section aria-label="Resultados" tabIndex={-1}` so it can receive focus; contents below). Exactly one of:
- **Loading (first load):** `div role="status"` with sr-only «Cargando candidaturas…» and 3 skeleton cards (aria-hidden) with the same geometry as a real card. While refreshing after a filter change the previous cards stay (no skeleton flash), the region has `aria-busy="true"`, and the counter updates when data arrives.
- **Error:** card `role="alert"` (`rounded-md border border-border bg-card p-6 flex flex-col items-start gap-4`) with `CircleAlert`, heading (Heading), body, and outline Button «Reintentar» (`RotateCcw`). On retry the focus moves to the results region and the loading state shows.
- **Empty (no applications, no active filters):** card with the text of the DS plus an **outline** Button «Añadir la primera candidatura» (assumption A-8: the header already holds the single primary action).
- **Empty by filters (0 results, ≥ 1 active filter):** card with heading, body and outline Button «Limpiar filtros». Active means text, status, tags, work mode or seniority; sort alone never produces this state.
- **Populated:** `ul aria-label="Candidaturas"` with `flex flex-col gap-4`, one `li` per application.

**Application card** (`li > article`, `relative rounded-md border border-border bg-card p-4 lg:p-6 flex flex-col gap-2 hover:border-input has-[a:focus-visible]:ring-2 has-[a:focus-visible]:ring-ring`). DOM order = visual order:
1. `h2` (Heading, serif) containing the TanStack `Link` to `/applications/$id`; the link is stretched over the whole card with `after:absolute after:inset-0` (single tab stop per card; no other interactive element inside the card). Visible text is the title; an sr-only `, {company}` follows it so two cards with the same title are distinguishable. Hover: `underline underline-offset-4`.
2. `p` Label `text-muted-foreground`: «{company} · {location}»; without location only «{company}» (no dangling separator).

### 2. Detail — `/applications/$applicationId`

**Header** (`flex flex-col gap-4`), DOM order = visual order:
1. Back link: `Link to="/applications"` (`ArrowLeft`, `text-primary underline underline-offset-4`, Label, `h-11 inline-flex items-center gap-2`) with text «Mis candidaturas». It does not preserve filters (assumption A-9).
2. Row `flex flex-col gap-4 lg:flex-row lg:items-start lg:justify-between`:
   - Title block `min-w-0`: eyebrow «Expediente», `h1` = title (Display, `break-words`), `p` Body «{company}» with muted « · {location}» when present.
   - Actions `grid grid-cols-2 gap-2 lg:flex`: primary Button «Editar» (`Pencil`, `Button asChild` → `/applications/$id/edit`, `h-11`), outline Button «Eliminar» (`Trash2` with `text-destructive`, label in foreground, `h-11`; opens the AlertDialog).

Status row `flex flex-col gap-2 sm:flex-row sm:items-end sm:gap-4`: `StatusBadge` of the current status, then a field «Cambiar estado» (`Label` + `NativeSelect`, `w-full sm:w-56`, the 7 statuses in enum order, value = current status), then `RequestStatus` slot (`role="status" aria-live="polite"`, always mounted).

**Status change behaviour.**
- Selecting a different status immediately updates the badge, the select value and the history (optimistic), then sends one `PATCH`.
- While the request is pending: select has `aria-busy="true"` and `aria-disabled="true"` (never `disabled`: a disabled select drops keyboard focus); the hook ignores further changes (single request in flight); the slot shows `RequestStatus loading` «Guardando…».
- Success: server response replaces the optimistic view; slot shows `success` «Estado cambiado a {label}.» (polite). It clears on the next interaction or after 5 s.
- Error: badge, select and history roll back to the snapshot; slot shows `error` «No se pudo cambiar el estado. Inténtalo de nuevo.» (polite). Focus stays on the select; the user can pick again. The message stays until the next attempt.

**Body** `grid gap-6 lg:grid-cols-3`; main `lg:col-span-2` (`flex flex-col gap-6`), aside `lg:col-span-1`. Sections are `section` with `rounded-md border border-border bg-card p-4 lg:p-6 flex flex-col gap-4` and an `h2`.

Main column, in this order, and nothing else (D-15):
1. **Datos de la oferta** — `dl` (`grid grid-cols-1 gap-4 sm:grid-cols-2`); `dt` Eyebrow, `dd` Body `break-words`. 2. **Etiquetas** — groups with Eyebrow titles, each followed by a `ul` of `TagChip`s (`flex flex-wrap gap-2`): «Stack tecnológico» (stack), «Se valora» (nice_to_have, `soft`), «Modelo de trabajo» (one chip with the work mode label), «Seniority» (one chip), «Contrato» (one chip), «Idiomas» (language). 4. **Texto original de la oferta** — only when `offerText` exists (it is `null` for anything created in Phase 2, so this section normally does not appear; no placeholder otherwise). `Collapsible`, closed by default, trigger text «Mostrar texto original» / «Ocultar texto original»; content `whitespace-pre-wrap break-words text-base`, rendered as text nodes (never HTML), no inner scroll area.

Aside column:
5. **Historial de estados** — `ol` newest first, `flex flex-col gap-4 border-l border-border pl-4`; each `li`: `size-2 rounded-full bg-status-*` dot positioned on the line, label (Label 600, foreground), date (Label `text-muted-foreground`, «12 oct. 2026»). The first entry also shows «Actual» (Eyebrow). Always at least one entry. During an optimistic change the new entry shows today's date and is replaced by the server's entry; on rollback it disappears.

There is no rounds section and no documents section (not even headings, empty states or disabled buttons).

**Delete flow.** «Eliminar» opens the AlertDialog. Cancel has initial focus. Esc, overlay click and «Conservar candidatura» (the dismiss button, named for its outcome) close it and return focus to «Eliminar». «Eliminar candidatura» (destructive) sends `DELETE`; while pending both buttons have `aria-disabled="true"`, the label becomes «Eliminando…» and closing is ignored. On error: the dialog stays open, a `RequestStatus error` line is added above the footer («No se pudo eliminar la candidatura. Inténtalo de nuevo.», polite) and focus stays on «Eliminar candidatura».

## Design Assumptions (this spec, not user decisions)

| ID | Assumption | Reason |

| A-5 | Detail history is newest first | The most relevant entry is on top; the oldest is the creation |
| A-6 | Stack chips show the 10 most frequent plus «Mostrar todas» | Dozens of tags would otherwise push the list off-screen |
| A-7 | Post-mutation navigation passes `{ focusHeading, notice }` in history state | Moves focus predictably and confirms the action visibly and audibly without a toast library |
| A-8 | The empty-state CTA is an outline button | The header already has the single primary action |
| A-9 | Back link does not preserve filters | Simplest behaviour that works on direct loads; may be improved later |

## Executor Notes (additive, consistent with CONTEXT D-12..D-18)

1. Status and tag-group class names live in literal lookup objects inside `status-badge.tsx` / `tag-chip.tsx`; no template-string class names.
2. `StatusBadge` and `TagChip` are covered by tests (D-18): status → token/icon/label mapping, `+N` logic, `aria-label="Quitar …"`, `aria-pressed`. Contrast and the 360 px layout are verified visually in Phase 6, not in jsdom.
3. The detail pod renders only the five sections listed; a test asserts the absence of «Rondas» and «Documentos» headings (D-15).
4. The tag input uses `normalizeTags` from `@tfm/contracts` and compares lengths to decide between «añadida», «Ya está en la lista» and «Máximo 20 etiquetas».
5. A pod never imports another pod: the list, detail and edit pods each own their copy of `getApplication` and their own labels/lookups (enum labels live in `common/` only if shared by all three; otherwise duplicated per pod).
6. Success notices and `focusHeading` flow through the scenes (scenes decide navigation); pods receive `onSaved`, `onDeleted`, `onCancel` as props.
