## Phase Goal

**As a** job seeker, **I want to** create, find, review and move my applications through their states, **so that** I have one reliable record of every selection process.

This plan serves one application by id. Plan 02-08 builds the detail that reads it, in the same wave.

<objective>
Serve one application by id with strict id handling (D-02): `GET /api/applications/:id` answers the Application or a clean 404 for unknown and malformed ids. This is the read side of the detail (APP-09, partial in Phase 2: the linked-documents clause is owned by Phase 5).

Purpose: the detail (plan 02-08), the status change and delete (plan 02-09) and the edit form (plan 02-12) all address an application by this id.
Output: `parseObjectId`, repository `findById`, service `get`, `GET /api/applications/:id` and its real-Mongo tests.
</objective>
