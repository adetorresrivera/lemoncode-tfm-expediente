## Assumptions (explicit, for the user to review)

- **SC1 wording vs D-04 (conflict flagged, locked decision honoured):** ROADMAP SC1 and FND-09 say a commit with a "type error" is rejected by the pre-commit hook; locked decision D-04 places `typecheck` in **pre-push** and only lint + Prettier on staged files. This plan implements D-04 exactly: lint errors are rejected at commit, type errors at push. If you want SC1 literally, add the line `npm run typecheck` to `.husky/pre-commit` (one line, reversible).
- **Format errors are auto-fixed, not rejected:** lint-staged runs `prettier --write`, so a pure formatting problem is repaired inside the commit instead of blocking it (RESEARCH Pattern 10). `npm run format:check` in every plan's verify still fails on unformatted files committed with `--no-verify`.
- **`--no-warn-ignored` (deviation from RESEARCH, documented):** RESEARCH's lint-staged line has no `--no-warn-ignored`; without it ESLint warns on explicitly passed ignored files and `--max-warnings=0` would reject any commit that stages `apps/web/src/routeTree.gen.ts`.
- **DS stylesheet stays byte-identical:** `apps/web/src/styles.css` is added to `.prettierignore` (Claude's discretion) so `cmp docs/design/expediente.css apps/web/src/styles.css` stays exact; plan 01-04 creates the file.
- Spec-less edge probes for FND-09 (unclassified) are lifted into truths (any rejected at commit, ignored generated file never blocks). No FND-09 probe is dropped.
